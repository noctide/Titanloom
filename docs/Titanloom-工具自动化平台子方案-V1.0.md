## 1. 设计依据与核心结论

依据总框架第8.3---8.6、10、12.3---12.5节，能力契约第3、6---10、18节，插件扩展第2---6节，后台公共任务与治理条款，填报第14、17---19节，考勤及部署方案，以及Shell方案。

工具自动化中心管理可复用工具、固定版本脚本与依赖、自动化计划、触发配置及跨模块动作编排。执行经公共命令、任务及受限宿主完成。它不接管数据流水线、业务审批、Agent目标规划，也不自建账户、权限、凭据或任务领取体系。

此前讨论中的Tool → Task → Workflow → Trigger → Run →
Artifact不作为统一对象链冻结：Task与Workflow在现有文件中已有明确含义，不能用同名新对象覆盖。本文采用Tool、ToolVersion、AutomationPlanVersion、TriggerBinding、TriggerOccurrence、AutomationRun、StepExecution及现有JobRun/JobAttempt、AssetRef。

数据处理平台现行方案已纳入边界核验：Pipeline / PipelineRun、算子
DAG、质量、血缘和 Dataset
发布仍归数据处理平台；工具自动化只通过固定版本能力或受控算子实现参与，不复制数据流水线语义。技术选型继承现行基线，不以文档中的旧版本号推断当前支持状态；实际安装和升级另按依赖治理核验。

## 3. 典型场景与首期范围

1.  手工选择获授权Asset，运行文件整理、转换、图片处理或报表工具，取得可下载产物。
2.  定时调用已发布Pipeline，核对正式Dataset后生成月报，不重新实现工时计算口径。
3.  消费质量异常或业务事件，生成清单并调用领域能力创建修订/审批请求。
4.  周期性调用考勤规则检查，跨月检查由考勤中心计算，异常由考勤领域产生 AttendanceAlert 等业务告警，Notification 只负责投递。
5.  为门户品牌排期提供持久定时触发适配，具体激活权限和BootAssignment状态仍归门户。
6.  Agent生成工具或计划草稿、测试和诊断；获准后通过同一发布及运行接口执行。

首期提供已认证Python工具宿主（运行用户编写的Python样板须先通过隔离宿主门禁G-ISO，门禁前仅运行受审查的内置工具实现，见ADR-016）、受控Capability调用、手工/一次性定时/周期/内部事件触发、有界顺序/分支/并行编排、持久等待、结果验证、恢复和完整人工管理路径。SQL计算通过数据能力或认证SQL执行器，不开放直连平台私表。JS、新语言、远程Agent、浏览器自动化或其他宿主按插件协议单独认证后接入，不预设运行支持。

本平台为B/S、Linux服务端执行。服务器不能直接操作用户Windows桌面、本地目录或个人软件；用户上传文件或使用获授权的连接器。个人电脑与企业数据保持既有隔离约束，测试使用合成或获准脱敏数据。

上述字段为拟定工程契约。ToolVersion可绑定已发布PackageVersion/Contribution；用户脚本发布也应构建为受管理产物并绑定认证宿主。无需每次运行安装新插件，普通工具实例与平台扩展安装分开管理。

## 5. 工具契约、输入输出和成功证据

工具版本至少声明：输入/输出JSON
Schema、参数默认值及范围、代码与运行环境摘要、能力依赖、网络/文件需求、effectModel、确定性、幂等策略、超时、取消、预算、验证器、日志规则、失败码和兼容范围。秘密配置只保存受控引用，不能进入源码、参数默认值、模型或普通日志。

输入优先使用AssetRef、Dataset/Query引用、领域资源及精确版本。参数经服务端校验，拒绝由请求传入任意可执行路径、解释器、数据库连接串或Shell命令。展示名称不作为稳定ID。

输出分为有界结构化结果、受控产物、领域操作回执。大量结果存Asset或通过数据处理发布，队列/模型只传必要引用。stdout不是唯一结果协议，退出码0也不是业务成功证据。验证器检查Schema、必需文件、摘要、记录计数或领域回执；验证器实现及版本受治理，不能仅信任脚本自报成功。

工具声明的权限只是所需权限。实际范围为执行主体、委托、工具运行授权、实例范围、输入/输出权限和资源预算的交集。工具作者或共享发布者的权限不会传给使用者。

## 6. 草稿、测试、发布和共享

流程：编辑草稿 → 校验契约与依赖 → 隔离构建 → 限额测试 → 影响与授权审查 →
发布不可变ToolVersion/PlanVersion → 在获准范围启用/绑定。

草稿自动保存采用revision，保留冲突和恢复路径。试运行是实际代码执行，仍需运行资格、隔离和预算。测试默认合成/获准数据、受控测试输出；禁止把dry-run参数当作可靠沙箱。外部副作用需测试适配器或明确批准的目标，否则只验证计划，不能宣称已执行验证。

个人工具默认本人可见，可分享给指定主体、空间/项目或申请公共发布。查看元数据、读取源码、执行、读取输入、下载产物、编辑、发布、触发配置和管理分别授权。个人数据处理成果不自动成为权威Dataset，权威发布沿用数据处理规则。

发布锁定源码、依赖、宿主绑定、能力契约、模板和验证器；更新生成新版本，不改变排队或运行中的实例。TriggerBinding升级必须显式选择新版本并验证权限/副作用。停止新用与紧急禁用分开，卸载前检查Plan、Pipeline、触发绑定、在途任务及历史保留引用。

无负责人、负责人离职或委托失效的共享工具/触发器进入交接或停用流程；不自动继承接任者全部权限。所有版本和运行有可联系的维护责任引用。

## 7. 自动化计划与控制结构

AutomationPlan拥有跨模块动作依赖，采用受控图Schema；图形编辑与高代码声明均编辑同一规范化定义。画布操作产生对定义的补丁，不能有两份互相漂移的权威源。发布时校验无环、类型、依赖版本、分支可达性、权限需求、预算和补偿引用。

  --------------------------------------------------------------------------------------------
  节点             行为                       限制
  ---------------- -------------------------- ------------------------------------------------
  CallCapability   调用已登记业务能力         固定契约及目标解析规则，执行前鉴权

  RunTool          调用固定工具版本           不接受任意代码替换版本

  InvokePipeline   启动固定数据流水线         等待Pipeline质量/发布等声明结果，不只看Job成功

  InvokeWorkflow   启动固定业务流程           关联WorkflowInstance，不复制审批节点

  Condition        根据结构化结果分支         有界确定性表达式，保存输入和选择结果

  Parallel / Join  有界并行及汇合             显式all_required或允许的部分成功策略

  Map              对已固定集合逐项执行       发布声明上限，运行固定集合和itemKey，逐项鉴权

  WaitUntil /      持久计时或等待相关事件     保存期限/游标/相关键，不占Worker
  WaitEvent                                   

  SubPlan          引用固定子计划版本         展开检查递归环、最大深度及总节点预算

  Verify           检查结果、领域状态及产物   失败阻止依赖它的步骤推进
  --------------------------------------------------------------------------------------------

首期没有任意while循环或无限递归；后续新控制节点经贡献协议和预算认证开放。Agent步骤通过已登记Agent能力实现，结果经Schema和验证器检查，不让模型临时改图或扩大权限。生成新的图只能成为新草稿。

并行默认所有必需分支成功才继续；显式容忍的可选分支失败以warnings和明细记录，不能吞掉必需步骤失败。某分支失败时未运行分支按策略停止，运行中分支申请取消并核对副作用，禁止立即假装整组已停止。

编排只实现领域推进规则；领取、时间唤醒、事件投递、租约和重试基础机制复用公共设施，表达式/图形组件可复用。不能为了自动化复制一个完整BPMN或数据ETL引擎。具体控制内核适配在工程阶段统一，未实现的复用组件不冒充已存在服务。

  外部Webhook       经《Titanloom-集成与消息通道子方案》的InboundEndpoint接入，M5开放事件接入   鉴权、防重放、限流、Schema及目标绑定由入站端点完成；自动化只消费其交付的受控事实并生成TriggerOccurrence
  -------------------------------------------------------------------------------------------

TriggerOccurrence保存observedAt与scheduledAt/occurredAt，不能混为一个"执行时间"。去重键：定时采用triggerId +
调度修订/epoch + UTC计划时刻；事件采用triggerId + 事件源标识 +
eventId。手工调用使用公共幂等键，后续重跑作为新的受控业务意图。

Occurrence接收事务持久化固定目标版本、来源、去重键和待调度记录/outbox。重复消息返回既有接收结果，不创建第二个Run。过滤不命中、已过期、无权、合并、跳过及过载拒绝保留可解释结果。

修改绑定使用期望revision，明确切换时刻与旧修订已领取Occurrence的处理；新修订不回溯重解释旧记录。触发器停用与事件/定时接收存在并发时，在提交边界复查当前状态；已接收任务按停止新用或紧急停止政策处理。

事件载荷仅包含受控引用和必要元数据。源 DomainEvent
表达所属领域已经发生的事实；TriggerOccurrence
表达自动化平台对该触发的接收、去重和处理事实，两者不得合并。消费者以当前权限获取详情，不能因事件由高权限服务产生而继承该服务权限。事件回放、重放范围与现行授权单独验证。

## 9. 调度、错过执行与防重叠

调度复用公共持久定时设施及任务准入；最小部署可由有界Runner配套控制服务完成，标准部署沿用Celery/RabbitMQ，但它们不拥有任务唯一事实。唯一活动调度者或带fencing的租约加Occurrence唯一约束共同处理重复扫描，不能只依赖进程内定时器。

定时保存IANA时区、规则及解析版本、UTC执行时刻、有效期和下一次检查点。界面提供下一批执行时间预览。夏令时不存在/重复时刻必须选择策略；建议不存在时刻跳过并记账、重复时刻只选较早一次，其他策略需显式配置。对账检测时钟回拨和前跳，进程内耗时与业务日历时间分别处理。

  策略       含义
  ---------- ----------------------------------------------------------
  skip       错过后不补跑，保存缺失Occurrence摘要
  coalesce   合并为一次有明确输入区间的运行；仅适用于声明可合并的任务
  catch_up   按遗漏计划时刻补跑，限制时间窗口、次数、速率和截止期

触发绑定必须声明misfire策略，不全局默认对所有任务补跑。月度业务不自动把多个期间合成一个；补跑固定每个期间、源水位和目标版本。积压超上限进入诊断/人工选择，不启动无界风暴。

防重叠键可按绑定、项目、业务期间或受控业务键定义。首期策略为有界queue、skip_new或受限allow_parallel，默认每绑定单活跃逻辑运行；不提供"杀掉旧任务就直接启动新任务"的默认替换策略。串行/去重政策不是资源授权，不能靠用户自报键绕过跨主体资源冲突。

存在外部副作用未知的旧运行时保持该业务键保护，完成对账后才决定放行；租约到期不自动视为已停止。服务重启从持久Occurrence和等待记录恢复，补偿与真实外部写入在恢复环境默认关闭。

## 10. 执行身份与长期授权

人工即席运行使用调用者与明确执行委托。长期定时任务绑定平台登记的服务主体或受管理最小委托，保存责任人、能力范围、目标资源、用途、期限和撤销路径，不能保存用户会话Cookie/Token来维持自动化。

创建定时任务不获得永久权利。触发接收、命令准备/提交、领取、重试、恢复、不可逆操作及交付边界都按当前权限核验。固定输入和实现用于可解释执行，不固定一份永不失效的权限快照。

Agent创建计划不等于把自己提升成服务身份。后续由服务主体执行的计划，必须经独立能力授权和明确范围配置；不能通过代建触发器绕过Agent三道门。涉及Agent的每个步骤继续按该步骤执行端和有效委托验证。

需要人工确认的动态目标在每次触发后准备并固定，转等待确认；无人值守不能自行确认。仅对明确获准的能力、目标范围、效果和限额采用无需逐次确认策略，且保留执行点检查。业务审批继续由领域流程完成。

## 11. 执行宿主、依赖与隔离

脚本不在API事件循环、Web主进程、Shell或Player内执行。工具版本绑定认证执行器与固定运行环境；首期Python版本沿用现行3.12.10基线，依赖锁文件及构建摘要固定。实际维护更新经兼容与安全核验，不能把固定版本理解为永久不更新。

构建与运行分开：包获取/构建使用批准来源、网络与独立额度，构建脚本本身也视为代码执行；执行阶段不临时pip安装任意依赖。支持内网离线包与受控缓存，记录许可证和来源；依赖缓存不包含业务秘密。

每次执行限制OS身份、CPU、内存、进程/线程、文件句柄、临时盘、输出体积、时间、网络目的地和并发。默认不挂载平台源码、宿主敏感目录或其他用户工作区；禁止继承平台数据库凭据。容器/进程名称本身不证明隔离，目标主机无法落实隔离时不开放个人或不可信代码运行。

允许工具拥有受控临时目录、只读输入和独立输出；路径正规化并验证范围，处理压缩包路径穿越、符号链接、解压体积和文件数量限制。正式文件通过Asset服务提交，不能把临时盘路径当成永久产物URL。

网络出口默认拒绝，按连接器、目标和用途授权，校验地址变化、重定向及内部/元数据目标；凭据由受控连接服务代理，普通工具接收secretRef而非原始密钥。平台数据只经Data
SDK/Query，合法外部数据连接按连接器治理。

Polars等多线程计算沿用spawn/exec隔离初始化、线程预算和取消清理要求，不能重造一套无界Python执行器。取消要覆盖子进程、查询及临时资源，实际停止证据决定终态。

## 12. 命令、状态和公共任务映射

人工、Agent、定时和事件统一经过能力网关；写入/控制按现行prepare →
确认（若需要）→
submit。固定契约、目标集合/版本、输入水位、参数和影响摘要；dry-run只准备，不表示无条件允许测试真实脚本。

公共JobRun状态原样沿用：queued、running、retry_wait、cancel_requested、reconciling、succeeded、failed、canceled、timed_out。JobAttempt是一次具体领取执行；终态JobRun不复活。effectStatus沿用none
/ committed / partial / unknown。

AutomationRun增加的是跨步骤领域状态，不能写回JobRun枚举。建议：pending、active、waiting、reconciling、canceling、succeeded、failed、canceled、timed_out；状态名待工程Schema认证。waiting保存原因、关联命令/流程/事件/时刻及期限，不占Worker。StepExecution保存尚未就绪、调用引用、等待、验证成功、失败、跳过及取消事实；执行租约/重试事实由引用的Job查询得到。

因此必须保持三层语义：AutomationRun
判断跨步骤业务编排是否完成；StepExecution
判断一个逻辑节点是否满足其领域成功条件；JobRun / JobAttempt
只判断具体后台执行是否完成。Job succeeded 不能证明 Pipeline
已发布、Workflow 已批准或 Attendance
已修正；反向也不能用领域拒绝去篡改已经真实完成的 Job 执行历史。

  -------------------------------------------------------------------------------------
  观察                         正确解释
  ---------------------------- --------------------------------------------------------
  协调唤醒Job成功              本次推进已提交，不代表整个AutomationRun成功

  工具Job succeeded            工具契约已完成，后续产物/领域验证仍按计划要求检查

  Pipeline根Job成功            仍需核对PipelineRun质量与Dataset发布

  Workflow启动成功             只表示已启动，批准/拒绝依Workflow结果

  某步骤外部效果unknown        Run进入reconciling并阻断依赖步骤，不能假报失败无副作用

  所有必需步骤完成且验证通过   Run才可succeeded，可选失败作为warnings明示
  -------------------------------------------------------------------------------------

计划整体超时与单Job超时分开，等待确认/审批的时间计入声明的总期限；人工决定到达晚于期限时留证据但不能自动复活终态。Run取消先阻止新步骤、取消有权取消的子任务，再核对已发生影响；取消晚于提交返回真实结果。终态Run重跑生成新Run并关联来源。

## 13. 可靠推进、事件竞态和循环保护

协调者通过公共任务领取机制执行短时推进，以Run
revision/条件更新保护状态迁移。创建步骤意图与outbox在事务中持久化；重复唤醒使用runId +
nodeId + itemKey等逻辑键找到已有StepExecution/命令，不能再次产生副作用。

异步调用先保存关联键和调用意图；确认/流程结束事件早于等待注册时，通过持久inbox及权威状态查询补齐。等待记录、事件消费去重和推进结果原子提交；事件通知可能重复或丢失，服务重启仍可按当前权威状态对账恢复。

按步骤依赖选择可运行节点，有界并行并记录分支输入和结果。数据依赖就绪不等于有权运行；副作用提交前再鉴权。外部系统不支持fencing时，数据库租约不能阻止已发出的请求，必须采用其幂等/查询回执或人工对账。

内部事件保持causationId、correlationId、来源Run/步骤与可验证来源链，拒绝用户任意伪造来源。触发定义检查明显自触发；跨计划设置因果深度、速率和预算上限，默认抑制声明的自回流。合法循环需显式策略，不靠无限相互触发实现循环节点。

## 14. 幂等、重试、恢复与补偿

至少区分Occurrence去重、命令幂等、步骤逻辑键和领域业务幂等。相同业务效果重试使用稳定业务幂等键，不按JobAttempt换键；刻意再执行是新命令，且核验领域唯一约束。幂等保留期覆盖允许的重投/回放窗口，超过窗口不默默当新请求处理。

  -----------------------------------------------------------------------------------------
  情形                                       行为
  ------------------------------------------ ----------------------------------------------
  读取或可证明未提交的暂时错误               有界退避，可配置抖动，受总期限和尝试上限约束

  Schema错误、无权、禁用、业务前置条件不符   不盲目自动重试，明确修复路径

  已知部分成功                               保留逐项效果，按业务幂等恢复未完成范围

  网络超时但可能已外部提交                   reconciling，按回执/业务键查询；禁止先重发

  检查点兼容且输入/实现固定                  经验证恢复，保存检查点及验证器版本

  检查点不兼容、输入无法固定                 拒绝假恢复，创建新Run并预览重执行影响
  -----------------------------------------------------------------------------------------

自动执行重试在非终态 JobRun 内通过新的 JobAttempt
或等价尝试完成，不构成新的 AutomationRun
业务意图；人工重跑终态执行必须区分"仅重新执行同一领域步骤"与"重新发起自动化运行"，后者生成新的
AutomationRun 并关联来源。JobRun 的 retry / cancel / failure
不能直接写成 AutomationRun
的业务终态，协调器必须依据步骤语义、已发生效果和领域结果进行判定。Run恢复只重做允许的节点，已成功副作用节点不机械重跑。复用旧结果需重新验证权限、保留期、输入依赖、Schema和确定性，记录复用来源。

补偿是新的独立受控命令，不是数据库回滚或删除运行记录。计划声明哪些动作有补偿、目标、前置版本、顺序和限额；默认沿已完成依赖的反向顺序执行，但实际业务可另定。补偿自身可失败或需要审批，不能覆盖原结果；原Run保留partial/committed效果及compensationRefs和结果摘要。

外部已发送通知、已下载文件或已完成业务审批通常不能恢复到"没发生"。工具可报告已知效果与建议，不能承诺全链路原子性或恰好一次。

## 15. 人工确认与业务审批等待

技术影响确认使用公共CapabilityCommand确认记录；借用归还、考勤审核等业务决定使用WorkflowInstance或对应领域命令。两者不能互相冒充，自动化只保存引用和结果验证条件。

等待不占Worker、数据库长事务或长期资源Reservation。唤醒后重新取得预算并鉴权，确认过期、资源revision改变、委托失效或风险升档时重新准备。用户关闭浏览器不丢失等待，Shell待办入口呈现所属服务的权威任务。

工具输出或模型建议不能作为伪造的人工确认。即使工作流批准，执行点仍检查目标、版本和当前权限；审批结果只证明对应业务决定，不授予额外能力。

## 16. 产物、数据出口与文件交付

输出先在受控暂存区生成，完成大小/格式/摘要/安全及业务验证后登记Asset和ArtifactManifest，随后执行授权交付或领域发布。以提交意图/回执和对账处理"文件已生成但登记失败"，清理前查引用和运行占用，不能误删正式或共享检查点。

每份产物记录toolVersion/planVersion、runId/jobId、输入版本、参数摘要、生成时刻、类型、数量、内容摘要及输出权限来源。敏感输出至少遵循输入和目标的授权/分类政策，不因工具是共享的就公开产物。列表、日志、预览、下载和模型交付分别鉴权。

结果成为Dataset必须调用数据处理的暂存、质量和发布能力；工具不能直接宣称一个文件已是权威Dataset。BusinessRecord、考勤和知识修改只经所属命令。邮件/聊天等发送动作经《Titanloom-集成与消息通道子方案》的出站通道交付，接收人和内容是受控参数，需相应通道及发送授权；通道上限与出网守卫由该方案规定。

临时文件、失败输出、正式产物、日志、检查点及回执分别设保留策略。临时文件不持久保存短期下载URL，产物保存稳定AssetRef；到期清理复用公共资产与依赖治理。

## 17. Agent、个人工具与能力目录

Agent可发现获准工具、查询契约、生成草稿、测试、准备运行、查看状态及提出修复，也可在授权后发布/启停/执行。能力发现不授予源码、输入、日志、下载或执行权限。代码注释、事件载荷和工具输出均为不可信内容，不能改变系统权限或发布政策。

自动化目录中的工具实例并非每个都必须是独立模型Tool。通用工具运行能力只能引用已发布且可授权的ToolVersion，并解析其声明的目标与效果，不能接受任意代码形成run_anything。需要独立业务授权的工具动作登记专用Capability；内部算子/节点保持内部实现。

模型生成代码先作为草稿，在隔离构建与测试后发布。模型不得自行降低风险级别、打开范围开关、替换执行身份或确认自己的高影响命令。R0/R1/R2+、impactLevel、operationKind及effectModel完全沿用公共规范，不发明另一套脚本风险枚举。

数据可直接从工具输出交付Asset或领域能力，不必经过模型。给模型的Schema、样本、错误和结果都遵守modelDelivery策略、脱敏和预算。日志中的秘密即使被脚本意外打印也不得按原文提供模型；日志脱敏只是补充，核心仍是不向普通脚本暴露原始凭据。

## 20. 资源治理、部署与性能

复用平台总池、任务类别、空间份额和单次预算；CPU、内存、线程、DB连接、临时盘、日志/产物、外部调用、并发、重试、图节点与Map元素分别计量，不合成不透明总分。计划预算覆盖所有子任务和子计划，不能每层重新获得一整份额度。

准入原子预留，完成确认停止后回收。等待不占计算额度，但持久等待记录、定时扫描和事件积压仍有容量限制。长任务/重计算与低延迟操作分队列，队列深度与最长等待有上限；资源不足明确排队、拒绝或降级，不挤占整台共享服务器。

最小档沿用PostgreSQL持久任务与有界Runner；标准档沿用Celery/RabbitMQ和分组Worker。初期不因编排引入强制Temporal、Kubernetes或另一套Broker；后续更换控制引擎需验证状态、幂等、恢复和迁移等价。

测试按单工具、同类并发、混合负载、触发突发、长等待恢复、故障和长稳分层；记录排队/执行P50/P95/P99、吞吐、错误、资源峰值、对账时长及临时残留。具体配额、队列/图上限、期限、保留期和SLO必须部署前登记并实测，不从共享服务器的物理内存推导安全并发。

## 21. 安全、审计与恢复

输入路径、文件、脚本依赖、外部响应与模型结果都按来源边界验证。只允许登记的资源与网络出口，不提供任意SQL/Shell管理终端。权限或插件禁用后停止新准入，执行检查点及交付点阻止后续受限行为；已发生外部效果按回执核对。

审计记录主体、委托、维护责任、工具/计划/触发版本、命令、输入摘要、目标、审批、Job及Attempt引用、效果、验证和产物，秘密脱敏。运行日志、审计和指标分开，日志限额、轮转、截断有明确标识。

Worker崩溃先核对租约和效果，再决定重试；旧fencing
token不能提交平台内部结果。控制服务重启从持久图、等待、Occurrence及outbox恢复。事件保留不足时查询权威状态或人工接管，不把事件缺失当作"未发生"。

备份包含工具/计划定义、运行/触发记录及固定包/资产引用，联合恢复核验引用完整。恢复环境默认禁用真实触发、通知和外部写入；恢复后先检查备份之后的撤权、禁用与已完成外部效果，避免重复执行。恢复不自动补跑所有错过任务。

## 22. 三条验收业务链

### 22.1 文件工具人工闭环

用户上传获授权Excel/图片 → 选择固定ToolVersion → 准备影响及输出范围 →
提交Job → 受限Worker执行 → 验证产物 → 登记Asset →
有权用户预览/下载。重复提交不重复接收，失败保留明确阶段，输出不会自动成为公共资产。

### 22.2 月度效率报表

按明确业务时区触发月度Occurrence → 固定业务期间与来源版本/水位 →
调用已发布Pipeline → 等待质量及Dataset发布 →
工具查询已发布结果并生成报表 → 验证Asset →
发布到获授权位置或生成待办。岗位、考勤、工时的口径归数据/业务领域，自动化不重新算一遍。输入不具备可固定性时记录明确的现场解析策略及快照，重试不漂移。

### 22.3 考勤异常与修订

消费排班/规则变化事件或周期检查 → 调用考勤跨月核验能力 →
固定异常引用及版本 → 按允许策略创建修订流程 → 等待业务决定 →
通过考勤命令修订 →
发布领域结果供数据处理消费。自动化不直接改排班表，拒绝/过期不当作批准，结果unknown不盲目重提。

## 24. 建设顺序与工程交付

阶段一：工具Schema、固定版本构建、受限Python样板（须先通过隔离宿主门禁G-ISO，门禁前仅运行受审查的内置工具实现）、公共命令/Job接入、人工运行、验证/产物/审计与取消，完成A01---A03及相关安全恢复基线。

阶段二：计划图、跨域调用、有界顺序/分支/并行、持久等待、对账/恢复、人工确认和业务流程关联；实现月报与异常修订的受控样板。

阶段三：定时/事件Occurrence、错过与并发策略、长期身份、事件竞态及循环保护、Shell入口和运行图；阶段一至三共同构成完整首期基线，可靠性不是后期可选装饰。

阶段四：根据真实需求认证新语言、外部宿主、更多控制节点和规模化调度；每项单独通过边界、兼容、许可及资源验收。

工程交付：OpenAPI/JSON
Schema、工具/计划清单、状态迁移和Run/Job映射、数据库唯一约束、事务/outbox设计、宿主隔离配置、密钥代理、策略矩阵、预算/SLO与保留配置、兼容/恢复和真实副作用测试。只用截图或脚本正常退出不能完成验收。
