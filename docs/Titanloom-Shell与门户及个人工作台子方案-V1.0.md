## 2. 核心不变量

1.  ShellContext是界面上下文，不是授权凭证；服务端按真实主体和资源权威归属裁决。
2.  主页访问权不传递为数据、附件、嵌入页、插件或业务动作权限。
3.  主页作者、当前访问者和Player展示身份分别处理，不互相继承。
4.  主页布局与可视化内容分别拥有唯一可编辑源；布局只引用内容，不复制第二份页面代码。
5.  已发布WorkspacePageVersion、BootExperienceVersion和引用的Release保持不可变。
6.  主页发布、激活和可视化Take是不同动作；主页不向On-air热推代码。
7.  个人布局不修改公共主页；公共模板更新不静默覆盖个人修改。
8.  任意高代码、第三方可执行UI按隔离宿主运行，不直接注入门户DOM。
9.  启动宣传与必要初始化并行；宣传失败不阻断启动，认证授权失败不回退放行业务。
10. 模块、Agent和重内容按需加载；所有卡片共同使用页面与设备预算。
11. 人、Agent和自动化使用同一受控能力；安装扩展不等于启用或获得业务授权。
12. 文档版本不代表软件交付、性能达标或外部接口已验证。

## 4. 导航、入口与深链接

导航面向现行正式业务能力域：智能管家、表单平台、考勤签到、工具自动化、数据处理、数据可视化、知识与文档。具体部署根据启用范围、服务状态、资格与资源预算呈现入口；是否显示为一级导航属于产品配置，不改变领域所有权，也不要求所有部署全量安装。

全局提供空间切换、搜索、待办、消息、Agent入口、语言和个人菜单；空间/项目层提供目录、公共主页和模块入口。桌面端左侧导航依次为首页、我的工作台、各业务能力域入口和管理入口（空间/项目设置、平台管理）；平台管理的二级导航见后台治理 6.1。平台管理、空间/项目设置和领域管理继续分层。

内部链接使用稳定资源引用，由路由解析器取得所需上下文。用户直接打开表单、待办、看板或任务链接时，登录及开屏后恢复原目标。认证前保存的返回目标视为不可信输入，按站内路由与目标策略校验。外链检查协议与目标，不转发平台凭据；脚本协议禁止，外部嵌入须登记。

不存在、无权、未部署、未启用和暂不可用在授权允许的诊断粒度内区分；对未授权主体不得泄露资源存在性。收藏和最近访问保存受控引用，展示时重新过滤，失效引用可清理。

默认主页按当前范围的有效配置解析；找不到可用版本时展示最小导航与诊断，不自动跳入另一空间或扩大访问权。浏览器前进后退和刷新按稳定资源路由恢复，敏感上下文不放URL。

## 5. ShellContext与切换协议

ShellContext包含workspaceId、projectId、locale、displayTimezone、theme、routeRef及contextEpoch。作用域与资源ID是请求上下文，不能替代服务端鉴权。模块声明需要的字段，Host按最小集合传递；Token、Cookie、密钥及其他模块数据不作为通用上下文。

切换过程：请求切换 → 模块离开保护 → 保存/保留草稿或取消切换 →
终止旧范围请求和订阅 → 获取新范围授权配置 → 增加contextEpoch →
挂载/更新目标模块。切换失败保持可解释的旧状态或安全导航页，不混合两边内容。

每次界面请求绑定上下文代次；旧请求即使无法真正取消，其迟到响应也不能写入新工作区。服务端长任务保持创建时的范围和委托，不随界面切换。恢复隐藏模块时重新检查授权和数据新鲜度。

显示时区与业务时区分开。语言、显示时区改变不改写业务日、考勤周期和历史事实。登出、会话失效及撤权时关闭相关嵌入会话、订阅并清理受限缓存；已经交付的内容无法承诺远程抹除。

## 6. 主页、工作台与模板

### 6.1 范围与内容

提供平台默认、空间/项目主页和个人工作台。导航中的"首页"指当前空间或项目的共享主页：同一范围的成员看到同一布局，各卡片按访问者自己的权限取数，典型内容为宣传轮播、公告（9.1）、今日出勤统计（考勤业务区块，考勤 20）、效率统计（已发布看板卡片）和常用入口。"我的工作台"是本人的个人布局。登录后默认进入哪一个由空间配置决定。个人工作台以本人日常使用为目标；个人主页可以发布并授权他人访问。个人主页和个人工作台可使用同一对象模型，但拥有独立的发布/激活选择，分享不会意外暴露正在修改的个人草稿。

支持链接、普通卡片、业务区块、自定义代码卡片、已发布看板和基础3D；拖拽、缩放、分区、主题、多尺寸预览、高代码内容入口均保留。普通可信卡片按Schema渲染；复杂代码、看板和3D在可视化中心或登记插件中制作，再引用固定版本。

基础3D仍属于现行首期范围：GLB/glTF、基础几何体、变换、材质、灯光、镜头、动画、点击、数据绑定和高代码扩展由可视化方案细化，Shell负责嵌入及预算。专业CAD、精细网格建模、复杂仿真和重型GIS不因此加入首期。

### 6.3 保存、发布、激活与回退

公共流程：草稿保存 → 校验 → 生成不可变版本 →
受控激活。发布与激活分别记录，即使UI支持一次提交，也要正确呈现部分成功。激活以期望revision比较并交换指针，防止两个管理员互相覆盖。

个人普通布局允许合并连续拖动后自动保存，并在本人已有发布/激活权限且校验通过时自动生成、激活个人版本。界面显示保存和生效状态；自动保存不自动分享，不自动发布新增可执行代码，也不扩大权限。保存失败保留可恢复编辑，不显示已保存。

固定pageId/releaseId、插件版本及配置快照。引用升级形成新主页版本，不能运行时解析latest。激活失败保留原指针；运行中某依赖失败则局部降级，不偷偷回滚整个主页。回退重新检查当前权限、禁用策略及依赖，不能复活已撤销内容。

模板更新提供差异预览；用户选择应用到个人草稿，冲突显式处理。同一卡片编辑、删除与编辑冲突不得最后写入者静默覆盖。服务端保存为准，本地缓存仅在明确敏感度及清理策略下启用；未成功保存的数据不承诺崩溃可恢复。

### 6.4 分享与删除

首期分享面向平台内已认证且获授权的主体，链接只是定位方式。主页授权不传递到内嵌内容；分享界面提供按目标身份模拟的受控可见性检查，但检查不能代替访问时鉴权。匿名主页访问为后续独立能力。

删除、退役与物理清除分开。当前激活、模板、历史引用、审计与保留要求纳入依赖检查。删除卡片只解除布局引用，不删除Dataset、Asset、Release或业务记录。

## 7. 嵌入、响应式与交互协调

普通观看按当前访问者建立受限EmbedSession，不使用作者权限，不向iframe提供控制台Cookie。无人值守展示使用登记的Player身份，不能把个人工作台会话改作无人值守播出凭证。

布局采用平台Schema，React Grid
Layout等库状态通过适配转换；不将库内部状态作为长期权威契约。组件声明最小尺寸、宽高比、密度、响应式、暂停与恢复要求。Shell负责外层布局，组件负责内部文字、图表、数字、间距、相机与交互区域同步适配。保持可读性下限，空间不足时换布局、折叠或进入详情。

图片放大、视频、轮播和自定义展播复用现行可视化能力；跨边界弹层由Host验证意图。Shell管理全局遮罩、焦点、滚动锁和返回位置，嵌入内容不得覆盖身份与授权确认界面。关闭面板不等于取消服务端任务。

首期支持zh-CN/en-US，机器ID不翻译，业务正文不自动翻译。验证长标题、日期、键盘导航、焦点恢复、对比度、减少动画偏好和触控。复杂编辑器可声明设备范围，但必要查看、跳转、跳过及确认应有适用路径。

## 8. 模块及Shell扩展协议

扩展点包括模块入口、业务卡片、全局动作、侧栏面板和BootRenderer；复用Contribution、Binding、Enablement、PackageVersion，不建立平行插件目录。导航登记不构成Capability授权，内部Renderer不自动成为Agent
Tool。

模块描述符至少声明moduleId、精确实现与协议版本、路由前缀、资源解析器、语言资源、所需上下文、资格/可用性信号、hostKind、离开保护、恢复策略、budgetProfile及健康诊断。重名路由、冲突入口、缺必需契约在安装或启用时拒绝。

建议生命周期：prepare、mount、updateContext、suspend、resume、unmount。每次调用有超时、取消信号与实例ID；卸载可重复调用，须清理计时器、事件、订阅、媒体与渲染资源。不能假设所有模块都可无损挂起：无法保留的模块先保存恢复引用再卸载。

可信第一方模块可在批准的Shell进程运行；第三方UI及任意高代码使用经认证的隔离Origin宿主。受控消息包含协议版本、实例/会话标识、请求ID、动作与Schema化载荷，校验来源窗口、Origin、作用域和有效会话，限制大小、频率与超时。导航、尺寸、关闭和资源请求分别允许，不提供任意执行或任意API转发。

模块更新不热替换正在编辑的页面；新会话使用批准版本，旧会话提示安全切换。紧急禁用优先于固定版本。Shell不依赖所有扩展启动成功，可选模块失败局部隔离，必要治理服务失败拒绝相关准入。

聚合投影可重建，不拥有业务事实；来源失败显示部分/未知，不把无数据显示为零。结果、摘要、数量和缓存都受权限约束。索引只是发现入口，点击与操作再次鉴权；撤权后旧摘要不继续展示。分页、超时、扇出和返回数量有预算，不一次扫描所有模块或将全平台内容交给模型。

待办只有一个入口：表单审批、考勤申报审核、数据处理隔离区修补、智能管家待确认操作等各领域待办都进入同一个收件箱，按来源分组和筛选。领域页面里的"待我办理"只是该收件箱按来源筛选的快捷入口，不另建第二套列表。

### 9.1 公告

公告是门户发布的正式告知，归 Shell / 门户服务。它与启动宣传（第 11 节）分开：宣传不承担必读和确认；公告也不承担审批或业务确认。

  ------------------------------------------------------------------------------------------------------------------
  对象                       最小信息                                                      规则
  -------------------------- ------------------------------------------------------------- -------------------------
  Announcement               announcementId、scope（平台 / 空间 / 项目）、owner、revision   稳定身份

  AnnouncementVersion        标题、正文、附件 Asset 引用、是否必读、受众规则、生效与        不可变；发布、撤回、过期
                             失效时间、置顶、发布人与时间                                  分别记录

  AnnouncementReceipt        主体、versionId、确认时间、终端类别                            只由本人写入；不可撤销
  ------------------------------------------------------------------------------------------------------------------

受众按组织、部门、角色和项目成员匹配，规则与启动体验的受众匹配相同（11.3），只有受众内且当前有权访问该范围的人能看到。正文和附件按业务正文处理，不自动翻译；附件访问仍由 Asset 服务鉴权。

必读公告在首页公告区和公告列表置顶，本人确认前保持"必读"标记。"我已阅读"写入 AnnouncementReceipt，绑定具体版本。正文有实质修改时发布新版本，发布人选择是否要求重新确认；只改错别字也形成新版本，但可不要求重新确认，两种选择都记入审计。首期不以必读公告拦截进入业务；如需强制阅读后才能继续，另行设计并评审。

确认统计以发布时解析出的应读名单为基线，之后新进入受众的人员单独计入并标明。发布人按授权范围查看确认率和未确认名单，可向未确认者发送提醒；提醒经 Notification 投递并受限频控制。已读通知不等于已阅读确认，阅读确认也不等于同意或业务签署。

撤回后不再展示，已有回执和统计保留；过期公告自动下线并进入历史。智能管家可以起草公告和整理确认情况，发布、撤回须人工确认；任何主体都不能代他人写入阅读回执。

## 10. 全局Agent入口

Agent从全局侧栏、资源页或选中文本启动，可跨领域调用已授权能力。发起上下文明确列出资源、版本、选中内容和用途；不自动采集整页、隐藏组件、浏览历史或凭据。页面切换不改变已有Agent任务来源，新增上下文显式追加并重新验证模型交付权限。

Shell展示进度、证据来源、影响预览、确认、取消、恢复与结果回链；AgentTask
由智能管家领域拥有，目标领域 Run 与公共 JobRun
分别由其权威服务拥有，Shell
只保存受控引用和展示投影。人工确认绑定具体命令及版本，不由Renderer或插件自绘假确认绕过公共流程。面板关闭不取消任务，退出登录撤销相关会话；长任务按既有委托有效期和执行检查点处理。

Agent可以建议布局、生成草稿、检查引用和配置宣传排期；修改、发布、激活及停用分别鉴权，不能通过编辑主页扩大自己的资源权限。Agent不可用时人工导航、编辑、发布及业务办理保持独立。

## 11. 启动体验与品牌宣传

### 11.1 启动并行与必要依赖

Bootstrap尽早开始必要初始化：会话/身份、权限上下文、当前门户配置、批准的必需模块描述和目标路由。只初始化当前入口需要的内容，Agent状态、通知、搜索及其他模块不作为全平台ready的硬依赖。

启动展示单独加载并有短期加载截止时间；已超过展示机会窗口则本次略过，避免用户开始操作后突然弹出。关闭展示不取消必要初始化。首期内置单图、轮播、静音视频；HTML/CSS、Canvas、WebGL、3D等按已认证BootRenderer协议扩展，不把任意HTML上传直接执行作为首期能力。

登录前只显示明确批准为公开的素材与配置投影，内部部门、角色、人员和排期详情不交付匿名端。定向内容在身份与受众核验后才匹配。企业宣传内容不承担必读公告、审批或已确认凭证。

### 11.2 对象与配置

  ----------------------------------- ------------------------------------------------------------------------------------------------
  BootExperience                      experienceId、owner、scope、名称、访问与管理策略

  BootExperienceDraft                 baseVersion、revision、内容、展示参数、降级策略

  BootExperienceVersion               versionId、Schema、精确Asset/Renderer版本、配置、摘要、发布信息

  BootAssignment                      assignmentId、revision、versionRef、scope、audience、schedule、priority、frequency、activation

素材字节归Asset服务，Boot对象保存关联。排期由BootAssignment承担，不另建重复Campaign引擎。"品牌与启动体验"是后台管理入口。

内容配置包含type、精确assetRefs、rendererBindingRef、适配方式cover/contain、背景及受控参数。宣传海报默认优先完整可读，预览裁切；视频静音播放失败时降级海报或退出。配置包含目标展示时长、平台硬上限、加载超时、触发条件及跳过策略。退出和跳过控件由可信Shell掌握，本方案始终允许用户跳过；目标时长不阻止主动跳过、故障退出或紧急停用。

### 11.3 排期与冲突选择

时间保存明确时区，排期使用起点包含、终点不包含的区间。跨日按排期时区判断；涉及夏令时的歧义/不存在时间在保存时要求明确处理，不能静默猜测。

先过滤已激活、范围适用、当前授权、受众匹配、有效时间及频次可用的候选，再按范围具体程度、显式priority和稳定assignmentId排序，取一项；不轮播多个活动以延长等待。范围顺序为个人、项目、空间、平台；组织/部门/角色用于受众匹配，不形成互相不可比较的隐式优先级。多受众冲突由priority解决，同级同优先级显示冲突提示并使用稳定排序兜底。

预览按指定时间、时区和有权模拟的受众显示候选、淘汰原因及最终命中；不能通过模拟接口读取无权人员信息。发布新排期记录差异，激活使用revision核对并检查资源与权限；未来定时激活沿用受控调度及幂等规则，不依赖浏览器一直在线。

### 11.4 频次语义

支持冷启动、明确的登录事件等触发；普通页面跳转和模块切换不重复触发。可配置每次、每日首次、某活动首次等频次，键包含assignmentId、频次策略版本、主体和周期。仅替换素材默认不重置频次；重新宣传需要显式更新频次策略并预览影响。

已登录按账户和排期时区计算；匿名按本浏览器记录，不承诺跨设备一致。实际开始可见展示后才记录，加载失败不计成功展示；跳过是结束原因，不是业务确认。同一客户端会话去重；账户跨设备并发只保证尽力控制，不承诺严格一次。严格一次须另行设计原子领取、超时、隐私与可用性取舍。

### 11.5 状态与退出

平台状态为initializing / ready / degraded / failed，宣传层为idle /
loading / showing /
closed，并记录completed、skipped、timeout、load_failed、renderer_failed或disabled等原因。宣传结束与平台ready互不代替。

  情形                   行为
  ---------------------- -------------------------------------------
  ready且仍showing       按策略展示，允许立即跳过
  initializing且closed   轻量真实加载反馈，可定位失败阶段
  可选服务失败           degraded进入可用区域，明确受影响能力
  必要身份/权限失败      关闭宣传，显示登录/错误处理，阻止相关访问
  素材或渲染失败/超时    轻量默认内容或直接关闭；不无限重试

关闭后释放媒体、网络、计时器及渲染资源并恢复焦点。播放时如页面隐藏，暂停并按策略退出，不恢复后补播一段过时宣传。普通停用停止新展示，紧急禁用尽快结束在线展示；离线已交付内容无法保证立即撤回。

## 12. BootRenderer与媒体治理

BootRenderer是Shell宿主的一类版本化贡献。建议暴露mount、pause、resume、destroy及ready/error事件，配置以Schema校验；destroy幂等。BootContext只含viewport、theme、locale、受控素材访问、关闭请求与有限导航意图，不提供业务Token、任意API、DOM或凭据。

渲染器可以报告加载进度，但不能伪造身份授权初始化进度、延长硬截止时间或删除跳过控件。普通定制内容使用隔离宿主，退出控件和计时由Shell维护。浏览器线程阻塞时定时器也可能延迟，不能把前端watchdog写成绝对故障隔离；不可信渲染器上线必须实测可退出性，不满足时限制为静态媒体或经认证实现。

Asset访问、缩略图、海报及派生媒体复用现有服务，处理派生任务使用JobRun与受限Worker。是否支持分段读取、预加载和转码按媒体服务工程契约验证；缓存键包含内容版本及适用授权维度，内部素材不得进入公开共享缓存。撤回后拒绝新交付并清理受控缓存，已下载字节不承诺销毁。

尺寸、解码后像素、帧数/时长、码率、文件体积、并发解码、缓存和渲染复杂度都纳入准入。跨Origin保护数据边界，不自动等于独立CPU/GPU硬配额。

## 15. 资源预算、性能与可观测性

首次仅加载Bootstrap、必要Shell、授权配置与目标模块；业务中心、Agent、搜索、重图表及3D按需加载。有限预加载，不让每张卡片按整机额度运行。可视区外、后台或隐藏内容暂停可暂停工作；恢复时校验权限及新鲜度。

服务器对查询、文件、并发、队列、结果大小和超时实施可执行限额。浏览器对请求、组件数、解码、动画及渲染复杂度做准入、监测、主动降级；CPU、JS
Heap和GPU的可观测性依环境而异，未知项明确标记，不能声称具有OS级硬限额。

参数登记至少覆盖：Shell加载预算、模块加载超时、卡片并发、订阅数、查询扇出、结果大小、配置大小、媒体预算、预加载/缓存上限、Boot加载截止及展示硬上限、3D活跃实例、历史版本和展示记录保留期。数值上线前确定并实测，不在设计稿编造保证。

性能分开测量Shell可交互、目标模块可用、首批可见卡片完成及宣传展示时长。覆盖冷/热缓存、窄带/高延迟、目标终端、多个卡片、重媒体和后台任务压力。记录P50/P95/P99、错误率、长任务、请求量及可观测资源；建立目标值、配置上限、实测值三列。

日志含traceId、上下文代次、模块/组件实例、版本、阶段、失败码和退出原因；不记录Token或默认完整业务内容。审计记录发布、激活、分享、排期与管理控制；高频性能指标及展示记录有界采样和保留，不逐帧写审计。

## 16. 故障恢复与数据维护

卡片失败局部占位并允许重试；引用失效保留诊断，不自动改用最新版。可选聚合服务异常显示部分/陈旧而非零。模块失败可返回最小导航。必要授权失败关闭受影响内容。禁止无界重试，离开时清理请求与运行资源。

配置和版本存于PostgreSQL，资产字节通过Asset适配层管理。元数据、引用与资产备份需能一致恢复并核验。恢复环境默认不激活真实宣传排期、不发送真实通知、不启动外部副作用；切换生产前复查恢复点之后的撤权和紧急禁用。保留及物理清除复用公共政策。

Shell升级验证Schema迁移、旧版本读取、组件协议和语言资源兼容。迁移不改写已发布字节，必要时生成新版本。回退应用代码不自动回退数据或ACL；不可逆迁移给出前向修复或恢复路径。

  S07                     多窗口改同一卡片        检测冲突，保留可恢复修改

  S08                     个人自动保存与分享      保存不自动分享或发布新增代码

  S09                     模板更新                预览差异，不覆盖个人修改

  S10                     多排期命中              与指定时间受众的预览一致，稳定排序

  S11                     匿名与定向宣传          登录前无内部受众、素材或配置泄露

  S12                     开屏失败、超时、跳过    可退出，必要初始化继续，状态真实

## 18. 实施顺序与工程交付

阶段A：Schema与公共契约、最小Shell、资源路由、上下文切换、主页草稿/版本/激活、授权与并发闭环。

阶段A内部分为A1与A2：A1为最小Shell、资源路由、上下文切换、授权与并发闭环；A2为主页草稿/版本/激活。A2在A1出口后、阶段B之前交付，实施路线按此排序。阶段B的"固定Release嵌入"与可视化方案阶段C的主页嵌入为同一项联合交付，共同验收。
阶段B：个人/公共工作台、布局与模板、业务卡片、固定Release嵌入和现行首期基础3D、待办/消息/搜索及Agent入口适配、公告与阅读确认、移动端导航。

阶段C：图片/轮播/视频启动体验、排期、受众、频次、发布停用、故障降级、媒体及性能验收。

阶段D：经过认证的第三方Shell
UI和自定义BootRenderer，逐宿主验证隔离、退出、兼容与预算。首期内置能力保持完整人工操作路径。

工程交付包括JSON
Schema/OpenAPI、状态转换与不变量、数据库迁移、能力描述符、事件Schema、Host协议、权限矩阵、预算配置、可重复验收及恢复演练。前端沿用现行React +
TypeScript +
Vite基线，不因外部动画案例新增平行前端体系；具体版本按现有依赖治理核验。

## 20. 决策与未决工程参数
