# Titanloom · 后端详细设计 · 插件宿主 · Shell · 平台管理（M1 部分）

> 版本：V1.0｜日期：2026-10-17｜状态：维护者已确认（设计页 sketch-backend-m1-shell v1，H 节 7 处 2026-10-17 "同意"）；数值为起点值，M1 实测后校准。
> 定位：M1 除三个底座之外的三项交付：插件宿主契约底座（插件阶段 A）、最小外壳（Shell A1）、平台管理最小闭环（后台治理 P1）。后续阶段（插件热更新与替换、第三方隔离、首页版本、依赖图、配置激活等）只写边界。
> 依据：插件与扩展体系 1、1.1、2.2、6、6.1、6.2、8；总框架 8.6；Shell 4、5、18；后台治理 2、5.1、6.1、18；ADR-023、ADR-026—ADR-030；后端详细设计总图、身份与权限、命令与任务、公共设施。

## 1. 插件树

-   **运行内核**（根，不可卸载）：读清单、排装配顺序、为每个插件建作用域、转发插件间调用。
-   **底座插件**（不可停用）：身份与权限、命令与任务、公共设施、能力目录、配置。缺席或不健康时拒绝业务准入，不回退为放行。
-   **官方内置插件**（可停用、可卸载）：表单、考勤、自动化、数据处理、可视化、知识、管家，以及 Shell、平台管理、集成。
-   **市场插件**（第三方）：隔离宿主验收（G-ISO）前不能安装；首期市场只有官方插件与皮肤包。
-   **清单**（H1，契约 plugin-manifest）：每个插件（含底座）一份，写明身份与版本、提供的服务与扩展点、需要的服务与扩展点（含降级方式）、登记的能力 / 功能 / 页面 / 导航 / 插槽 / 定时 / 文案 / 搜索、排空时间。**没写进清单的东西运行时登记不进去**；CI 与启动时都校验。皮肤包只有样式令牌，不提供服务、不登记能力。
-   **组合版本**（契约 composition-version）：某一时刻哪些插件、哪一版、启用与否的锁定快照；每次启停生成新版本、记原因与上一版、可回退；底座必须启用。

## 2. 装配与启停

启动：读全部清单与当前组合版本 → 依赖检查（有环拒绝并列出环，缺必需提供方不激活）→ 拓扑排序（底座先）→ 逐个激活，所有登记经作用域并拿到撤销句柄 → 健康检查（底座必须正常）→ 开放业务准入。

停用内置模块（不重启）：准备时列出影响（依赖它的插件与降级方式、引用它的首页卡片、自动化、排队任务）→ 确认后生成新组合版本、插件进入排空 → 新请求立即按已停用拒绝（`CAPABILITY_DISABLED`），导航、插槽、能力入口撤下 → 在途请求与任务在排空时间内完成，默认 60 秒，插件可在清单声明，上限 10 分钟（H7），超时强制撤销并记"被停用中断" → 内核按登记逆序撤销路由、插槽、订阅、定时、文案等 → 写审计、发 `platform.composition.changed`。业务数据不删，重新启用后恢复。

**M1 范围**（H2）：清单、依赖检查、装配顺序、作用域登记与自动撤销、组合版本与回退、内置模块不重启启停。**不在 M1**：不重启更新到新版本、替换为另一实现、第三方隔离运行，随插件阶段 C；M1 期间升级代码 = 排空后台程序后重启两个进程（约几十秒），页面显示"正在升级，稍后自动恢复"。

## 3. 插件之间

-   **服务**：需要方在清单声明"需要某服务某版本区间"，运行时由内核给转发器；提供方不可用时转发器返回 `DEPENDENCY_UNAVAILABLE`，需要方按清单声明降级（跳过这一步 / 暂停 / 自身停用）。同一范围一个服务只有一个活动提供方。
-   **扩展点**：定义方写清贡献格式、调用方向、超时、基数、是否接受第三方；贡献方的权限 = 自身授权 ∩ 调用者权限，扩展点不顺带授权。M1 用内置模块自测机制，首批真实贡献在 M2–M3。

## 4. Shell 后端（A1）

-   **我的外壳**（H4，契约 shell-me）：登录后一个请求返回姓名与部门（兼岗列全部）、语言、显示时区、皮肤、范围菜单、当前范围与范围代次、导航（已启用模块 ∩ 本人可用，不可用的标"暂不可用"）、功能状态（可用 / 可申请 / 隐藏）、首页指向（本部门，没有则直属上级）、语言包版本、待办与消息角标（来源不可用为空，不为 0）、快捷圈五格、权限版本、组合版本。按（账户、权限版本、组合版本、范围）缓存，目标 0.1 秒内返回。前端不自行计算权限。
-   **切换范围**：返回新范围的外壳，范围代次 +1，旧范围迟到的响应由页面丢弃（Shell 5）。
-   **登录与返回**：登录、会话由身份与权限处理；Shell 只负责登录后回到原目标，并校验其为站内相对地址。

## 5. 稳定链接（H5，契约 resource-resolve）

分享、通知、待办、收藏、最近访问使用 `/r/<模块>/<类型>/<编号>`，**不含部门**；对象换部门或项目后旧链接照常可用。解析时问所属模块对象归属，再问权限，结果：

| 结果 | 页面 |
| --- | --- |
| 打开 / 切换范围后打开 | 直接打开；切范围时提示 |
| 不是你的部门 | 回到本部门，不说明对象是否存在、叫什么 |
| 没有权限（能知道它存在时） | 统一"没有权限 · 申请" |
| 模块暂不可用 | 说明页（H6） |
| 已删除 / 不存在 | 只对有权者说明已删除；其他人与"不是你的部门"一致 |

浏览器地址栏中的页面地址可以带范围，但对外一律用稳定链接。

## 6. 平台管理 M1（P1）

-   最小闭环：建空间（导入人事 → 部门空间、建跨部门项目）→ 授权（角色、授权、功能开放、查权限、生效进度）→ 运行（运行中心）→ 排障（总览"需要处理"、审计、按错误编号查请求）→ 受控处置（停用账户、收回授权、停用模块、暂停领取，均走命令并审计）。
-   **平台管理不存业务对象**（H3）：后端只把各模块数据汇总成页面（只读），并把按钮转为所属模块的命令。
-   **总览**：各模块登记"需要处理的事"及计数，每 1 分钟汇总，按查看者权限过滤；某模块汇总失败显示"暂时取不到"，不显示 0。
-   P2、P3 再做：配置修订与激活、依赖图与运行图、业务参数页完整编辑、插件详情页、集成中心、凭据轮换、备份恢复、告警规则编辑。

## 7. 健康与"暂不可用"（H6，契约 plugin-health）

-   三态：正常 · 降级 · 不可用。内核每 15 秒检查；连续 3 次不可用才标"不可用"并进运行中心与总览。
-   不可用模块的导航入口不隐藏，标"暂不可用"，点入为说明页（哪里不可用、从何时起、管理员是否已知）；没权限的入口才不显示。其他模块照常可用。

## 8. 已确认的决定（2026-10-17）

| # | 决定 |
| --- | --- |
| 1 | 每个模块（含底座）一份清单，清单外登记不进去 |
| 2 | M1 只做内置模块不重启启停；不重启更新、替换、第三方隔离随插件阶段 C；M1 升级 = 排空后重启 |
| 3 | 平台管理后端不存业务对象，只汇总与转发命令 |
| 4 | 一个请求拿齐"我的外壳"，按权限版本与组合版本缓存，目标 0.1 秒 |
| 5 | 稳定链接不含部门 |
| 6 | 模块不可用时入口不隐藏，标"暂不可用" |
| 7 | 停用模块默认排空 60 秒，插件可声明，上限 10 分钟 |

取舍见 ADR-030。

## 9. 给执行 Agent 的技术细节

**清单**：`manifest.yaml`，Pydantic 校验，CI 与启动双重检查；`titanloom.*` 仅官方内置。

**表（schema `platform`）**：`plugin`（id、version、kind、removable、manifest_digest、state active / draining / disabled / failed、health、health_at）、`composition_version`、`registration`（plugin_id、kind、key、handle）、`health_probe`、`attention_item`。

**内核**：Kahn 拓扑排序；`scope.register_*` 返回撤销句柄入栈；准入中间件按插件 state 拒绝；排空后逆序撤销；撤销幂等。M1 不实现多版本并存。

**接口**：`GET /api/shell/me`、`POST /api/shell/scope`、`GET /api/shell/resolve?ref=`；`GET /api/admin/overview`、`GET /api/admin/plugins`、`GET /api/admin/health`、`POST /api/admin/plugins/{id}:disable|enable`（准备 / 提交，影响等级高须确认，底座返回 `CAPABILITY_DISABLED`）。返回目标仅接受站内相对路径，拒绝 `//`、协议与反斜杠。

**契约**：plugin-manifest、composition-version、shell-me、resource-resolve、plugin-health；测试 `test_contracts_part12.py`。

**验收要点**：循环依赖拒绝；缺必需提供方不激活；清单外登记报错；停用后无残留登记；停用期间新请求被拒、在途按排空时间完成；组合版本可回退；底座不可停用；我的外壳 P95 < 100 ms（实测）；范围切换后旧响应被丢弃；稳定链接不泄露存在性；模块不可用显示说明页；总览按权限过滤、失败不显示 0；"建空间 → 授权 → 运行 → 排障 → 受控处置"端到端演示。

## 10. 设计页的写法（2026-10-17 维护者同意）

此后每个后端设计页只向维护者提出真正要拍板的决定（影响业务、改动代价大），每页最多 3 处；纯技术默认值（保留天数、重试次数、超时秒数等）由设计者直接定，在页尾列"已替你定的默认值"一张表，维护者扫一眼，有异议再提。每页开头先给一段"这页说了什么"，细节折叠。
