# Titanloom · 后端详细设计 · 总图

> 版本：V1.0｜日期：2026-10-17｜状态：维护者已确认（设计页 sketch-backend-overview v1.1，H 节 9 处 2026-10-17 "9 处都按建议"）；文中数值为起点值，M0 在 2 核 2G 主机实测后校准，写成部署参数。
> 定位：各子方案定"做什么、谁负责、规则是什么"，本文定"后端怎么搭"：进程组成、一次请求的处理顺序、读写两条路、任务排队、代码分层、数据库约定和公共设施。M1 起每个模块的后端设计页（表、接口、状态图）都建立在本文上。

## 1. 组成

首期部署档为"最小"（部署拓扑 3）：一台主机上 4 个常驻程序，外加受控文件目录。

| 组成 | 做什么 | 不做什么 |
| --- | --- | --- |
| 门卫（Nginx） | 发前端静态产物；把 `/api` 转给主程序；压缩、HTTPS；限包体、限速；按主程序的 `X-Accel-Redirect` 发送文件字节 | 不做任何业务判断 |
| 主程序 `titanloom-api` | 一个进程，包含全部模块（模块化单体）；处理全部用户、外部 Agent 与模块间请求 | 不跑长任务，不搬大文件 |
| 后台程序 `titanloom-runner` | 一个进程：任务领取循环、定时投放、outbox 投递；重活在子进程执行 | 不接用户请求 |
| PostgreSQL | 全部业务数据、权限、任务表、审计、搜索索引；按模块分 schema | — |
| 受控文件目录 | 上传与生成的文件；只经主程序鉴权后由门卫发送 | 不对外直接暴露 |
| 出网守卫 | 所有出站请求的唯一出口（清单内地址），密钥经 SecretRef 解密使用 | 不回显密钥 |

外部 Agent、命令行工具和网页走同一套接口、同样的权限（能力契约 5.1）。

**内存预算（起点值）**：Nginx ~10 MB；主程序 ~150–200 MB；后台程序 ~100 MB（重活子进程另算、跑完释放）；PostgreSQL ~200–250 MB、连接上限 20。合计不超过主机实际可用内存的 70%。不装 RabbitMQ、Celery、Redis。

**为什么是一个主程序**：一人开发、一台 2G 主机，拆成多个服务的通信、部署、排查成本马上就有，单独扩容的好处现在用不上。代码里按模块严格分开（第 5 节四条硬规矩由 CI 强制），以后需要时可把某个模块拎出去，不重写。

## 2. 一次请求的处理顺序

例：唐宁（装配一部）在签到页提交"10-02 补下班卡 17:32"。

| 关 | 做什么 | 没过时用户看到什么 |
| --- | --- | --- |
| 1 门卫 | 包体过大、频率过高直接挡 | 统一报错卡 |
| 2 你是谁 | 服务端会话（HttpOnly cookie）解析为 Principal；账户停用直接拒绝 | 跳回登录页，登录后回到原页（Shell 4） |
| 3 在哪 | 按记录真实归属判断范围，不信客户端声明；范围菜单只是"当前看哪"，不是权限 | 别的部门地址 →"这不是你的部门"，回到自己部门，不露内容 |
| 4 功能开放 | 只对登记为功能的"新建 / 发起"类能力（后台治理 4.6） | 入口带「申请」；"没人"时入口不出现 |
| 5 权限 | 角色 + 数据范围；管家代办时另过三道门（能力契约 5.4） | 统一"没有权限 · 申请"组件 |
| 6 业务规则 | 各模块 domain 层判一次；前端提示只是提前告知 | 表单标红写原因；超上限照样可提交并标记 |
| 7 一次写完 | 一个事务内写业务记录 + 幂等记录 + 审计（高影响）+ outbox 事件 | 失败即失败、可重试，不重复写 |
| 8 后台接手 | Runner 消费 outbox：投递待办、站内信、刷新搜索索引 | 用户已看到"已提交"；投递失败自动重试，再不成进运行中心 |
| 9 回复 | 返回结果或 accepted 回执（异步命令，能力契约 6.6、7.2） | — |

## 3. 读和写两条路

- **读**：过第 1–3、5 关后直接查库。大表一律服务端分页（键集游标），图表单次结果上限默认 5 万行、管理员最高 50 万行；已关账期间查询结果长期缓存，数据处理发布更正时自动清掉相关缓存（可视化方案已定）。普通读取不写审计；查看审计、导出名单等敏感读取要记。
- **写**：统一走命令，先准备再提交（能力契约 6.1）。准备返回影响摘要且不改任何数据；高影响须确认；提交时带上准备时看到的版本，期间有变化则要求重看。低影响的小改动可准备与提交一步完成，规则相同、不弹确认。

## 4. 后台任务排队

不用消息队列软件，用数据库里的任务表排队（能力契约 8.4 最小 Runner）。

- **排队**：要做的事写进 `execution.job_run`，写进即不丢；主机重启或程序崩溃后接着做。
- **领取**：Runner 领取时创建一条 `job_attempt`，绑定 workerId、租约到期时间和单调递增的 fencing token（契约 job-attempt.schema.json）；执行中每 5 s 续约，租约 30 s。程序死了不续约，租约过期后可被重新领取；旧持有者的状态写入因 fencing token 不匹配被拒。
- **两条道**：轻道（通知、待办投递、缓存刷新、搜索索引）并发 4；重道（Excel 导入、数据处理、报表生成）并发 1，在受限内存与 CPU 时间的子进程里执行，超时终止并记失败。并发数是部署参数，换机器改参数即可。
- **定时**：调度到点往任务表放一件，同一绑定同一计划时刻只放一次（唯一约束）；错过不补跑、上次没跑完跳过（自动化方案已定）。
- **失败**：确定没做成的按策略重试（自动化默认 2 次）；不确定做没做成的不自动重发，先进 reconciling 核对，核对不出交给人（能力契约 8.3）；连续失败进运行中心"待核对"。
- **升级**：任务量超出单机时换"标准档"（消息队列 + 多个后台程序），领取协议相同，业务代码不改（部署拓扑 3）。

例：门禁导入第 41 批——入站端点收下并存原文、写导入任务 → Runner 重道领取、逐行写签到记录（每行带来源事件编号，重复推送不重复写）→ 中途重启则租约过期后重新领取、从检查点续做 → 完成后更新考勤格子，异常进疑似漏报并发待办 → 运行中心可见每一步。

## 5. 代码分层

每个模块切成同样的四层；执行 Agent 只改自己模块的目录（开发项目划分规范）。

| 层 | 职责 | 不许做 |
| --- | --- | --- |
| `api` | 对外口：路由、请求 / 返回结构、能力编号、格式校验、转交 | 写业务规则 |
| `app` | 办事流程：按第 2 节顺序调用授权、规则、写库、发事件 | 直接拼 SQL 绕过 store |
| `domain` | 纯业务规则与状态迁移 | 碰数据库、网络、时钟（时间由参数传入） |
| `store` | 本模块的表、读写方法、迁移 | 读写别的模块的表 |

```
apps/api/titanloom/
  kernel/        # 公共工具：错误格式、请求编号、时间、分页、幂等
  access/        # 底座：身份与权限（含部门空间、功能开放）
    api/  app/  domain/  store/  migrations/  tests/
  execution/     # 底座：命令、任务排队、后台程序
  facilities/    # 底座：文件、审计、通知与待办、文案、搜索索引
  shell/  admin/  plugin_host/  integration/
  forms/  attendance/  dataproc/  visualization/
  automation/  knowledge/  agent/
  main.py        # 主程序入口
  runner.py      # 后台程序入口
packages/contracts/  # 接口、事件、错误码、状态的正本
```

**四条硬规矩**（CI 检查，违反不能合并）：

1. 模块之间只能引用对方的 `api` 层。
2. 每个模块一个 schema 和一个数据库账号，账号只能写本 schema；迁移用 owner 账号。
3. 接口、事件、错误码先写进 contracts，代码照着生成和测试，不手写第二份。
4. 业务规则只在 `domain` 写一次；前端提示不能代替后端判断。

## 6. 数据库约定

- 每个模块一个 schema（access、execution、facilities、search、attendance、forms……）。跨 schema 只存对方编号，不建外键，靠对账保证一致。备份与恢复整库进行（后台治理 12.3）。
- 每张业务表的通用列（契约 record-common.schema.json）：

| 列 | 含义 |
| --- | --- |
| `id` | UUIDv7，应用侧生成，永不改变、不给人看 |
| `code` | 给人看的短编号（如 AU-0013、JR-8840），需要的对象才有；编码规则可改，不影响内部关联 |
| `revision` | 乐观锁版本；后提交者收到"有人刚改过" |
| `created_at` / `created_by` / `updated_at` / `updated_by` | UTC 时间与 Principal；显示时按用户时区 |
| `status` | 草稿 / 生效 / 停用 / 归档等，各表用 CHECK 约束取值 |
| `scope_kind` / `scope_id` | 归属：dept（部门空间）/ project（跨部门项目）/ personal（个人） |

- **业务数据不直接删除**：界面上的"删除"在后台是停用或归档，真正抹掉走资源目录清理流程（后台治理已定）。个人草稿等可直接删除的对象，由各模块在其设计页标明。
- 表名 snake_case 单数；分页用（排序键, id）游标，禁止无界查询；精确数值用 numeric，对外按字符串编码。

## 7. 公共设施

| 设施 | 设计 |
| --- | --- |
| 登录 | 首期平台自带账号密码（Argon2id 摘要），服务端会话表 `access.session`；cookie HttpOnly、Secure、SameSite=Lax；写请求校验 CSRF 令牌（双提交）。企业统一登录按 OIDC 预留为可选提供方。首次部署由引导流程创建第一位管理员，之后关闭引导（后台治理 4.1）。自动化与报表用服务身份，不能登录网页 |
| 实时更新 | 每个标签页一条 WebSocket，消息只带事件类型与资源引用，客户端按需拉取；断线指数退避重连，超过阈值退为轮询，间隔默认 15 s（业务参数 `shell.live.pollSec`） |
| 文件 | 上传落临时区 → 校验大小与类型（病毒扫描接口预留）→ 登记 Asset 版本 → 移入正式目录；下载每次鉴权后返回 `X-Accel-Redirect`，由门卫发送字节 |
| 设置类数据 | 业务参数、功能开放、文案存库，主程序读入内存，变更发事件刷新；带版本、可回退；代码不写死可调数值 |
| 出错 | 统一错误体 `{requestId, error:{code, messageKey, messageParams, retryable, recoveryAction, details}}`（契约 error.schema.json）；code 必须在 error-codes.json 登记；details 只给有开发者资格的人看；报错卡、管家分析、反馈都靠它（Shell 9.5） |
| 外部连接 | 一律经出网守卫（地址清单）；密钥以主机上的主密钥做信封加密存库（SecretRef），页面只显示"已设置" |

## 8. 界面文案

正本在后端（ADR-021、国际化规范）：

- 平台自带的每句文案有一个键，中英文存数据库，在平台管理 › 语言与术语维护，发布成版本、可回退。仓库 `i18n/` 只是出厂默认，部署时导入、只补缺的键，不覆盖后台改过的字。
- 前端只按键取字：打开页面时下载当前语言、按模块分块、带版本号的语言包，浏览器缓存，版本变了才重新下载；日期、数字、金额由浏览器按语言排版。前端代码不许写中文字句（工程规范 4.2）。
- 通知、站内信、群消息、导出表头、报错文字由后端按收件人语言生成。
- 用户建的对象名称跟着对象存中英两份（LocalizedText），不进语言包；用户填写的内容不翻译。

## 9. 全局搜索

顶栏搜索（Shell 9.7）背后的设计。

**能搜到什么**：名称包含即命中（不要求从头开始）；拼音全拼与首字母（多音字的几种读法都存）；打错一两个字母仍命中但排后；同义词（补卡 = 补签、OT = 加班）；中英两个名字；能直接做的操作（"补签""新建表单"）置顶；问句最后一行给"问管家"；知识正文走知识模块全文检索。

**排序**：完全一致 → 开头一致 → 拼音首字母 → 包含 → 相似；同档内本人常用与最近打开的、本部门的靠前。按类型分组（操作 · 人 · 表单 · 看板 · 数据 · 文档 · 自动化 · 平台管理），每组先出前几条。输入停顿约 0.15 s 出结果；最近搜索只存在本机。

**权限**：索引记录每样东西的归属范围与可见性摘要。查询先按范围过滤，取候选，打分后把前 50 条交所属模块复核；看不到的东西名字和数量都不出现。权限变化最晚几秒内反映到结果。

**索引来源**：各模块实现 SearchProvider（契约 search-provider.schema.json）登记可搜索的对象类型与可搜索操作；对象新建、改名、删除、换权限时发 outbox 事件，Runner 轻道几秒内更新 `search.search_doc`（契约 search-doc.schema.json）；每晚全量对账。索引不是任何数据的正本，可从各模块重建。

**实现**：首期只用 PostgreSQL——pg_trgm 相似度（GIN `gin_trgm_ops` 建在名称、拼音、别名拼接列上）+ 前缀 btree（`text_pattern_ops`）+ pypinyin 生成的拼音列（多音字组合上限 8 种）；同义词来自术语表（语言与术语 + 知识术语卡"也叫"），查询时扩展。目标：10 万条以内 0.2 s 出结果，M0 实测；中文 trigram 依赖数据库字符集与排序配置，不达标时改用自建二元分词列，再不达标找维护者另议。将来换专门的搜索程序，隔着 SearchProvider 与查询接口，模块不改。"意思相近、字完全不同"的语义搜索留接口（知识方案 RetrievalProvider），首期不做。

**操作登记**：各页面在登记页面动作时一并登记可搜索的操作（工程规范 4.4 页面声明），按用户是否有该功能显示。

## 10. 已确认的决定（2026-10-17）

| # | 决定 | 备注 |
| --- | --- | --- |
| 1 | 一个主程序 + 一个后台程序，不拆服务 | 模块边界由 CI 强制 |
| 2 | 内部编号 UUIDv7，给人看的用短编号 | 两者分开 |
| 3 | 首期自带账号密码，预留 OIDC | 引导流程创建首位管理员 |
| 4 | 重道并发 1、轻道并发 4 | 部署参数，M0 实测校准 |
| 5 | 业务数据不直接删除 | 可直删的对象由模块设计页标明 |
| 6 | WebSocket + 断线退回 15 s 轮询 | 间隔为业务参数 |
| 7 | 搜索首期只用 PostgreSQL | M0 实测效果与速度 |
| 8 | "意思相近"首期靠同义词表 | 在术语表维护；语义搜索留接口 |
| 9 | 搜索里能直接做事 | 页面声明时登记可搜索操作 |

架构取舍见 ADR-026。

## 11. 给执行 Agent 的技术细节

- **栈**：Python 3.12（uv、独立虚拟环境）· FastAPI + Pydantic v2 · Uvicorn 单 worker asyncio · SQLAlchemy 2.x（常规对象用 ORM，批量与查询用 Core / 参数化 SQL / COPY）+ psycopg 3 · Alembic（每模块独立迁移目录与 version 表）· PostgreSQL 16/17 · 前端 React + TS + Vite 静态产物由 Nginx 提供，生产不依赖常驻 Node。进程由 systemd 管理。
- **请求链**：Nginx → 中间件（requestId、会话 → Principal + InvocationContext，能力契约 5.2）→ 模块 api → app 按能力契约 5.4 顺序调用 access 授权 SDK（功能开放在基础授权前、仅对声明为功能的能力）→ domain → 单事务写业务 + idempotency_record + audit_event（高影响）+ outbox_event → 响应。异步命令按能力契约 7.2 同事务创建 Invocation、JobRun、outbox，返回 accepted 回执。
- **幂等**：写请求带 `Idempotency-Key`（客户端每次提交生成一次、重试复用），服务端以（主体, 能力, 键）唯一约束去重，同键不同载荷返回 409；业务键（如门禁 sourceEventId）另行防重。
- **任务领取**：在一个事务里 `SELECT id FROM execution.job_run WHERE state='queued' AND lane=$1 AND not_before<=now() ORDER BY priority, created_at LIMIT 1 FOR UPDATE SKIP LOCKED`，随后插入 job_attempt（fencing_token = 该任务上次 token + 1、lease_expires_at = now()+30 s）并把 job_run 置为 running、current_attempt_ref 指向它。租约与 fencing token 属于 JobAttempt（能力契约 8.1、8.4），job_run 不另存租约列。所有状态写入带（attempt id, fencing_token）条件。调度以（绑定, 计划时刻）唯一约束防重复。outbox 按 id 递增读取、至少一次投递，订阅方按事件 id 幂等。
- **数据库**：见第 6 节；`numeric` 精确值、`timestamptz` UTC、`status` 用 CHECK；跨 schema 无外键。
- **实时**：参数 `shell.live.pollSec`；消息体只含事件类型与资源引用。
- **搜索**：`search.search_doc` 字段见契约；查询流程：范围过滤 → 候选 200 → 打分 → 前 50 交 `check_visible` 复核 → 分组返回，不返回被过滤数量。
- **待 M0 实测**：内存账、轻重道并发、租约与心跳、10 万条搜索 0.2 s、中文 trigram 效果。
