## 1. 核心原则

1.  项目统一组织页面、组件、数据引用、媒体资源和节目单，资源通过稳定 ID
    引用。
2.  高代码编辑制作为主，组件拖拽与 Inspector
    辅助制作；页面代码及声明文件是唯一可编辑源，可视化操作生成可审查、可撤销的代码或声明补丁，不另存一套独立的拖拽页面模型。
3.  数据通过 Data SDK 和服务端权限检查获取，数据库凭据留在服务端。
4.  Studio 制作、Director 导播、Player
    播放分离；保存草稿不影响正在播出的版本。
5.  发布物不可变，Player 播放已经下载、校验和准备好的发布版本。
6.  按需查询、按需挂载、有限预加载；性能同时受 Display
    和物理设备预算约束。
7.  表现能力不设人为上限，运行资源必须有明确上限。
8.  图片、视频、轮播、弹层与页面切换共用生命周期和暂停协调机制。
9.  主页可以引用已发布看板、3D 场景和代码卡片；复用 Runtime
    与数据出口，门户布局和页面制作分别管理。
10. 控制台统一 React + TypeScript，正式业务计算通过平台 Dataset / Query
    交由经认证的 PostgreSQL SQL、Python / Polars
    或未来分析执行引擎完成；JS 负责表现及获授权结果的局部交互。
11. 筛选绑定字段而不连接图表；标题与报表的表现由作者以代码自由编写，适配、更新和权限由平台统一保证。

后端采用模块化单体起步，构建、转码和查询重任务使用有界后台任务队列。共享服务器上为服务进程、任务和连接池设置资源上限。

前后端明确分离：Studio / Director / Player
独立构建，通过版本化接口使用服务端能力；前后端支持独立部署与兼容窗口内独立升级，也允许同机同域部署。业务规则、权限及持久化由服务端负责，页面只承载表现和交互。前后端分离不要求微服务、微前端或每个模块独立服务器。

Studio / Director 使用 React、TypeScript、Vite，基础控件采用 Ant
Design，样式采用 CSS Modules 和统一设计变量，代码编辑使用 Monaco。 Ant
Design 只约束可信编辑器 / 管理控件，不约束用户高代码 Page 的 HTML / CSS
/ TS、隔离组件或 Player
画面；主题与样式不得从编辑器泄入页面运行沙箱。Player / Runtime 使用
TypeScript、iframe、按需 Web Worker；React
页面和组件采用与宿主兼容的固定依赖版本，原有 HTML / CSS / TS
高代码入口保留。常规图表使用 ECharts，地图资源使用 GeoJSON；基础 3D 采用
Three.js，React 组件采用 React Three Fiber
适配。媒体以原生视频元素为播放基础。命令通道使用
WebSocket，查询和资源使用受控 HTTP API。

后端复用平台 Python / FastAPI / Pydantic
模块化单体，持久化元数据明确采用 PostgreSQL，使用 SQLAlchemy / psycopg
和 Alembic；不自建另一套数据库或身份体系。业务数据全部接平台数据处理
Dataset / Query
出口，服务端控制面负责契约、授权、质量与路由，执行面首期采用 PostgreSQL
SQL / Python / Polars，未来扩展引擎不改变页面数据契约。文件通过统一
Asset API
提供，底层可接文件存储或对象存储。缓存有容量上限，多实例确需共享时采用平台缓存服务，Redis
按需部署，不保存唯一业务事实。

构建、转码等长任务复用公共 JobRun / JobAttempt 与
Executor；可视化领域拥有 Build / Transcode 请求的领域语义、Release
生成条件和结果引用，公共 Job
设施只拥有排队、领取、租约、执行尝试、超时与取消等执行事实。最小验证部署使用有界本地
Runner，标准部署可使用经部署方案确认的队列适配；Node.js 只承担前端及
Release 构建，媒体处理进入独立 Worker。控制台请求状态采用 TanStack
Query、少量 Zustand；页内 Data SDK / Query Manager
独立承担查询合并和生命周期，不为同一查询叠加两套周期刷新。语言包采用
i18next / react-i18next，格式化采用
Intl；版本锁定、离线包、测试与资源隔离执行总框架第 12.3---12.5 节。

### 2.1 门户主页嵌入

门户支持链接、普通业务卡片、自定义代码卡片、看板和基础 3D。布局由门户
WorkspacePage / WorkspacePageVersion 管理，可视化内容由 Project / Page /
Release 管理；主页使用 React Grid Layout
等布局实现时，内部状态转换为平台布局 Schema，不复制 Page
的第二份权威代码模型。

普通可信业务卡片由门户渲染并调用所属模块能力。复杂卡片、看板和 3D 在
Studio 制作或由登记的组件插件提供，构建成不可变 Release 后，在隔离
Origin 的嵌入宿主中运行。主页保存 pageId、releaseId、允许的 Context
参数及布局配置，更新引用需发布新主页版本。主页草稿不影响公共主页或
On-air；主页发布不发送 Take。访问平台、空间 /
项目及个人主页的权限由门户管理，不能靠链接可见性授权。

普通浏览使用当前访问者的受限嵌入会话，不继承主页作者的数据权限，控制台
Cookie 不进入 iframe。无人值守屏幕采用平台登记的 Player
展示身份。两类身份分别进入数据与附件服务裁决；引用已发布页面不会自动获得其
Dataset / Asset 权限。iframe 导航、弹层和点击意图经 Host
校验后执行，不允许页面任意控制门户。

同一主页可存在多个嵌入页，每个实例具有独立会话、Context
和生命周期，所有实例受一个浏览器设备总预算约束。该模式不改变展播 Display
稳态一个基础页的约定，不把每个卡片当作独占整机资源的 Display。不可见 /
后台实例暂停查询和动画，有限预加载；恢复时校验权限、数据代次与尺寸。复杂内容提供封面、打开按钮、加载失败和无权占位。

### 2.2 基础 3D 制作与渲染

首期提供 GLB / glTF 导入、基础几何体、位移 / 旋转 /
缩放、材质、灯光、镜头、动画、点击与数据绑定，以及高代码组件扩展。Three.js
负责渲染，React Three Fiber
是可替换适配层；业务对象和模型节点使用稳定标识，不将运行时对象引用作为持久化主键。3D
场景配置与单屏播放列表 Scene 采用不同对象类型，避免同名混用。

模型、贴图和解码器由 Asset
与构建清单管理，离线包包含必要依赖。资产导入记录坐标轴、单位、尺寸、来源和版本，加载前校验格式与预算；模型材质或贴图引用不得静默访问未登记外部网络。渲染对象、GPU
句柄和大型数组不放入通用业务状态树，生命周期由渲染适配器管理。

优先采用经目标设备验证的 WebGL 渲染路径；WebGPU 不作为首期前提。按
Profile
限制模型大小、几何复杂度、纹理分辨率、DPR、活动画布和动画数量，静态场景按需渲染，不可见场景停止帧循环。数据更新保留有效镜头和选中状态；缩放容器更新视口与相机，切页
/ dispose 释放 GPU、事件、定时器和订阅。加载、GPU
上下文丢失或超预算时有可观察的封面 / 低细节降级。

完整 CAD、专业网格建模编辑器、复杂仿真和重型 GIS 不属于基础 3D
交付。专业模型可在外部工具制作后导入；新的算法或渲染扩展通过同一组件及插件契约接入，并独立验收。基础
3D 进入首期 A / C，复杂定制仍在 E 阶段逐项交付。

## 3. 对象关系与项目组织

  --------------------------------------------------------------------------------------------------------------------------------------------------
  对象                                定义
  ----------------------------------- --------------------------------------------------------------------------------------------------------------
  Project                             页面、组件、资源、数据引用及成员的组织边界

  Page                                可构建、校验、版本化的页面包

  Component                           带输入、事件、数据契约和版本的可复用组件

  Scene                               单屏页面播放列表，配置顺序、停留时间和转场

  Display                             逻辑显示目标，具有分辨率、交互和声音配置

  Wall                                一组 Display

  Show                                将页面或 Scene 编排到多个 Display 的节目单

  Player                              承载 Display 的播放实例，登记所属物理设备

  Device Profile                      物理设备能力与验收基线，记录设备型号、分辨率、DPR、内存、显存、视频解码路数、查询并发上限及是否允许 WARM 预热
                                      GPU

  Dataset / Query Ref                 引用数据处理平台拥有的 Dataset / Query 契约及版本；可视化保存绑定、参数、刷新和展示配置，不复制其权威定义

  FieldRef                            引用数据处理平台登记的稳定字段标识；同义列由数据处理平台的字段映射归一，筛选、联动与下钻按 FieldRef 分发

  Filter                              页面或布局分组内的筛选定义，绑定 FieldRef，声明取值来源、默认值、展示模式与作用范围

  ReportDefinition                    生成式 HTML 报表定义，引用 Release 中的报表页面、筛选值、生成身份、触发方式与分发范围

  ReportInstance                      一次报表生成的不可变结果，绑定 snapshotId、数据水位与完整性摘要

  AssetRef                            引用统一 Asset
                                      服务拥有的图片、视频、字体、地图、模型及贴图等资源版本；可视化保存用途、构建和展示引用，不复制二进制权威对象

  Release                             锁定代码、组件、资源及数据契约的不可变发布包

  PlaybackSession                     一次页面、媒体或轮播播放的运行状态

  EmbedSession                        门户内嵌页面的受限访问者会话，记录所属主页版本、页面、权限与 Context，不替代 Player 身份
  --------------------------------------------------------------------------------------------------------------------------------------------------

这些对象通过引用关联，不构造成一条强制嵌套链。Page 可以出现在多个
Scene；Show 的 cue 指定目标 Display
和播放内容。物理设备分配独立于页面目录。

其中
VisualizationProject、Page、Component、Scene、Display、Wall、Show、Player、Device
Profile、Release、PlaybackSession、EmbedSession、Filter、ReportDefinition、ReportInstance
的业务语义归可视化领域；Dataset / Query 与 FieldRef 只保存受控引用，Asset 只保存
AssetRef。Release 是可视化领域不可变交付边界，不等同于
DatasetVersion、KnowledgeVersion、插件 PackageVersion 或公共 JobRun。

## 4. Page 与组件契约

Page 的 HTML/CSS/TS 定义表现与行为，page.json 定义 ID、入口、Display
Profile、能力权限、依赖和预算。queries.json
保存查询引用及刷新策略，filters.json 保存筛选定义；每个字段只有一个权威来源。

公共组件声明：Props、Events、Data Contract、Context
依赖、筛选排除（ignoreFilters）、最低尺寸、密度等级、生命周期、能力权限和版本。组件默认受作用范围内全部筛选约束，只声明例外，不声明与每个筛选器的连接。

参与拖拽与 Inspector 编辑的组件额外声明可编辑属性
Schema、默认配置及受支持的布局操作。自定义组件满足同一组件契约后可注册到组件面板复用；未提供可视化编辑声明的组件仍可通过代码使用，不要求平台将任意手写代码反向转换为可拖拽模型。

运行时钩子统一为
prepare、activate、suspend、resize、dispose。取消查询、清理定时器、订阅、事件监听器和
GPU 资源属于组件清理职责，Host 同时回收组件登记的资源。

组件版本在 Release
中固定。修改公共组件后，通过显式升级和构建验证更新使用方。

### 4.1 插件贡献与兼容

组件、renderer、layout、transition、media 和受控 UI 贡献映射总框架第 8.6
节的统一插件机制。
各贡献类型分别声明输入、输出、生命周期、权限、预算与兼容范围；renderer
适配层及 Release 固定规则延续现有设计，在工程 Schema
中验证创建、更新、暂停、销毁与资源释放，不另立一套架构。插件包、安装、范围启用和实例配置分别管理，默认不因安装而获得执行权限。清单登记入口、Schema、Host
SDK
范围、依赖、能力、语言包、生命周期和资源预算；未开放的类型或不支持的宿主组合拒绝安装
/ 构建。

Runtime 只加载当前 Release
锁定且仍获准使用的插件产物。普通停用可停止新引用并保留旧发布依赖；安全紧急禁用和撤权按平台策略遮蔽或降级受影响内容，固定版本不覆盖安全裁决。卸载前检查主页版本、Page、Release
和 On-air
依赖，仍被引用的产物不得直接删除。插件不自建查询出口，数据源插件不能被页面
import。

高代码不强制全部转成插件：项目内代码仍是可编辑源，跨项目复用或独立交付的实现再登记为组件
/ 插件。控制台第三方执行 UI 使用隔离 Origin，声明式贡献由可信 Host
渲染；插件调用取其获批运行权限与调用者权限的交集，Agent
继续受三道门约束。

### 4.2 插件包组成与宿主边界

可视化领域以插件包交付，内部仍保留 Studio、构建、Runtime、Director 与
Player 的职责。一个包可包含 editor、build、runtime
三类产物，每类独立声明入口、依赖、摘要、权限、预算和兼容范围。Player
只携带播放必需产物，不包含编辑器、构建工具、平台凭据或动态安装器。编辑器扩展通过契约注册面板及属性
Schema，不修改其他插件私有状态。

平台统一插件生命周期与页面 prepare／activate／suspend／resize／dispose
分层映射：平台管理宿主实例，页面管理展示实例；停用时双方幂等清理订阅、查询及
GPU。安装启用不等于页面激活，页面隐藏也不等于插件已卸载。

## 5. Studio、协作与辅助开发

Studio
布局：左侧项目树，中部代码编辑，右侧预览；可切换预览主视图。底部提供
Console、Data、Network、Performance、Dependencies 和 Errors。

制作方式以高代码为主，组件拖拽与 Inspector
用于加速常规搭建。布局、绘制、动画和交互保留直接编写代码的入口，表达能力不受内置组件清单限制，并遵守统一的运行契约。

  --------------------------------------------------------------------------------------------------------------------------------
  辅助操作                            对唯一代码源或声明文件的修改
  ----------------------------------- --------------------------------------------------------------------------------------------
  拖入组件                            插入组件引用及默认配置，生成后可继续手工编辑

  移动或调整组件尺寸                  修改布局声明；响应式布局优先调整网格位置、跨度及尺寸约束，不将拖动结果一律写成固定像素坐标

  修改 Inspector 属性                 按组件声明的可编辑属性生成定向补丁

  拖入数据字段                        修改已授权 Query 引用和字段绑定，不复制整份数据，也不绕过数据权限
  --------------------------------------------------------------------------------------------------------------------------------

拖拽和 Inspector 共用补丁机制，变更可

## 6. 页面生命周期与资源预算

资源状态：UNLOADED → LOADING → READY → DISPOSED；READY 页面可进入
SUSPENDED，并按需要重新激活。加载失败进入 ERROR，可重试或回退。

显示状态：HIDDEN、ENTERING、VISIBLE、EXITING。

播出属性：OFF_AIR、PREVIEW、ON_AIR。冻结和黑屏属于 Display
输出控制，独立于页面资源状态。

稳态每个 Display
一个基础可见页面。转场允许一个退出页与一个进入页短时共存，受时长和资源预算约束。完整
Page Dialog 是受控附加页面，最多一层，与基础页共享 Display 总预算。

WARM 是预备策略：加载下一页代码、资源和必要数据；只有 Device Profile
的剩余 GPU 预算不小于该页声明的 gpuReserve 时，才允许初始化图表或 GPU
资源，并保持隐藏和无周期动画；否则只预取代码、资源和必要数据。DORMANT
页面停止查询、动画、轮播和媒体播放，按内存策略暂停或销毁。

物理设备统一统计所有 Player、预监、转场、弹窗、视频解码和 GPU
使用量。活动页数量、显存、内存、查询并发、视频解码数量均由 Device
Profile 限定。

page.json、组件及插件的依赖、生命周期和预算为构建必检字段；缺失、非法值、目标
Profile 不支持或预算低于按规定场景测得的必要资源时，拒绝目标构建 /
准入，不能以空字段绕过 WARM 检查。基础 3D
和主页多个嵌入实例必须联合测量，单组件验收不代表组合可用。运行时超预算须降级、暂停或拒绝进一步挂载，浏览器协作限制不宣称为操作系统硬隔离。

调用。静态资源来自发布清单，网络访问通过

MessageChannel 和会话握手识别对端，不依赖通配来源信任。

EmbedSession 或 Player / Display

## 8. Data SDK、查询、缓存与快照

调用路径：组件 → Data SDK → Query Manager → 平台数据处理 Dataset / Query
服务 → 授权范围内的计算与数据对象。Data Service
复用平台服务或作为薄适配层，不另建连接原始业务库的查询旁路。

浏览器侧 Query Manager
负责同一页面内相同查询键的请求合并、消费者订阅与取消；服务端 Data
Service 负责权限检查、行数与体积限制、缓存及跨 Player
的结果复用。浏览器取消某个消费者只解除其订阅，不得越权取消仍被其他消费者使用的共享请求。

查询通过 queryId
和参数执行，服务端校验字段、参数类型、行列权限、最大行数、结果体积、超时、连接池和并发。大表格接入总框架第
12.3.1 节的服务端查询与选型门禁，表格 UI
不直连原始业务库，浏览器当前页不代表全量数据。聚合下推，明细分页。Context
只触发声明依赖字段的组件。

正式业务口径在所属服务端执行：SQL 做可下推关联聚合，Python / Polars
做数据加工；页面 JS / TS
仅做坐标、颜色、布局、动画及已授权有限结果的局部派生，不把已加载分页当作全量统计。禁止为图表或
3D 拉取全表后才做权限过滤。Worker
可辅助前端重计算，但结果体积、传输复制与主线程渲染仍受预算约束。

多用户并发、后端批任务与前端渲染分别治理。可靠事件及增量处理由平台实现；推送只是数据代次变化通知，Query
Manager 合并刷新并丢弃过期结果。UI
不因推送次数自行累计正式指标。精确十进制、大整数、单位与时间口径遵循总框架第
6.6 节，显示格式化不改变原始值。

缓存键由服务端生成，包含组织或权限域、数据源身份、Dataset/Query
版本、规范化参数、有效权限指纹及快照或实时数据代次。Release
影响查询行为时纳入键。页面不得自行声称权限范围。

缓存有
TTL、容量、淘汰、并发合并及权限变更失效机制。取消某个消费者只解除它的订阅，仍有消费者时不取消共享请求。结果携带请求代次，过期结果不得覆盖新筛选状态。

  模式                                行为
  ----------------------------------- ------------------------------------------------
  live                                按 Query

  snapshot                            预先生成结果集合，同次展示绑定相同

  mixed                               页面明确声明哪些 Query

快照记录 Context

### 8.2 筛选器与字段绑定

筛选器绑定 FieldRef，不与图表逐个连接。不同 Dataset 中含义相同而列名不同的字段，由数据处理平台的字段映射归一到同一 FieldRef；可视化只引用，不维护第二份映射。

Query 在契约中声明可接受筛选的 FieldRef 及参数槽位（filterable）。基于 Dataset 语义层生成的 Query 由平台推导；手写 SQL 的 Query 须显式声明参数槽位，平台不改写任意 SQL。一个 Query 只声明一次，无论被多少组件复用均不重复配置。

筛选值变化时，Query Manager 找出作用范围内声明该 FieldRef 的全部 Query，以新参数重新执行，只刷新受影响组件。图表点击联动与下钻发出同一形式的 FieldRef 取值，复用该分发机制，不另建联动链路；联动只改筛选值，下钻另行记录层级路径并提供面包屑和返回。

  字段           说明
  -------------- ------------------------------------------------------------------------------
  id / label     稳定 ID；label 使用语言资源键
  kind           单选、多选、日期区间、相对日期、数值区间、文本搜索、层级树
  field          绑定的 FieldRef
  options        静态值、授权选项 Query 或字典；高基数选项服务端搜索分页
  default        具体值、权限范围内全部或相对日期
  dependsOn      级联父项；父项变化时按规则清除失效子值
  scope          默认整页，可限定为布局分组
  presentation   展示模式，见下表
  operableBy     可操作角色，例如现场筛选；未授权角色只读
  applyMode      即时生效或确认生效；高成本 Query 建议确认生效
  maxSelected    多选上限

组件以 ignoreFilters 排除指定 FieldRef，例如全国对比图不受区域筛选影响；分区筛选通过 scope 限定到布局分组。筛选与 Query 粒度不同时，由服务端按 Query 声明的 grain 换算；日期区间统一左闭右开，相对日期由服务端按业务时区解析，前端不拼接区间。

筛选值只作为 Query 参数，由服务端校验类型与权限，禁止拉取全量后在浏览器筛选。选项只返回当前主体有权的取值，"全部"指权限范围内全部。区分未选择、全部与结果为空，结果为空时组件显示当前筛选无数据。多选值规范化排序后进入缓存键；选项 Query 计入页面查询并发预算。

同一筛选的取值来源按以下优先级裁决：导播锁定 > Show 共享 Context > 嵌入参数 > 用户操作 > 默认值。被上层锁定的筛选器只读显示并标明锁定来源。

  展示模式      行为
  ------------- --------------------------------------------------------------
  inline        在筛选栏常显
  collapsed     收入按钮或抽屉，显示生效数量；compact / portrait 默认采用
  hidden        界面不出现但生效，值来自默认值、嵌入参数、URL 或导播锁定
  conditional   按角色、终端或交互呼出，无操作超时后收起

隐藏只是展示行为，不是权限控制，数据范围由数据权限决定。隐藏或折叠的生效筛选须能被观看者识别，通常写入标题动态上下文；hidden 筛选取非默认值而页面未展示其摘要时，构建给出警告。无人值守触摸屏配置空闲超时，超时恢复默认筛选。

Studio 悬停筛选器时高亮受影响组件、灰显被排除组件。构建检查：没有任何 Query 接受的筛选字段告警，ignoreFilters 引用不存在的 FieldRef 报错，级联存在循环报错。

FieldRef、字段映射与 Query filterable 声明由数据处理平台提供，见数据处理子方案 12.6（拟定）。

### 8.3 报表模板与数据绑定

页面可用声明式模板直接绑定已登记 Query，生成随数据更新的 HTML 报表；复杂表现使用 Data SDK 订阅接口。两种入口共用 Data SDK、Query Manager、会话授权与缓存，对作者而言即直接取用数据处理平台的数据，但页面不持有凭据，也不绕过 SDK 请求接口。

模板提供值插值、格式化过滤器（数字、金额、百分比、日期时间，基于 Intl 并遵循总框架第 6.6 节）、列表循环、条件显示和数据元信息（数据时间、陈旧状态、snapshotId）。插值一律按文本插入；模板结构与样式由作者自由编写，数据值不作为 HTML、属性名、URL 或脚本解析，动态 URL 与样式值只能经白名单过滤器生成。模板不提供任意表达式求值，复杂逻辑使用高代码入口。

更新链路：数据处理平台在 Dataset 数据代次变化后发布代次事件；平台经 WebSocket 通知订阅页面受影响的 queryId 与新代次，通知不携带数据；Query Manager 合并通知后重新获取，丢弃过期代次结果；模板只更新值发生变化的绑定节点，列表按声明的行键增删改，不整页重绘；筛选、滚动、展开与交互状态保持不变，FitBox 区域随内容重新适配。转场与冻结期间暂缓应用；推送不可用时退回 Query 刷新策略。代次事件 `data.dataset.generation_changed` 与 Query 响应中的 dataGeneration 见数据处理子方案 12.6（拟定）。

### 9.2 标题与容器适配

Runtime SDK 提供 FitBox 容器适配能力，适用于标题、关键数值、徽标和单位块：内容按自然尺寸排版并测量，以 transform 等比缩放至完整放入容器，不溢出、不截断。不以调整 font-size 实现，避免浏览器最小字号设置导致溢出。

  参数         规则
  ------------ ----------------------------------------------------------------------------
  fit          contain 保持排版整体缩放；reflow 按容器宽度换行后再缩放
  maxScale     默认 1，不放大；大屏可显式允许放大
  最小缩放     由 Display Profile 的可读字号阈值与内容最小字号推算，不允许无限缩小
  留白         默认 2% 安全边距；阴影、描边、辉光等外溢效果可声明额外留白
  compact      可选精简版内容，用于极小容器

在最小缩放下仍放不下时，依次处理：reflow 换行后缩放；构建期按全部目标 Profile 检查，标题在下限仍放不下时拒绝构建，其他 FitBox 区域给出警告，由作者调整布局或提供精简版；运行时遇到意外尺寸（例如门户卡片被缩小）切换精简版，未提供时按下限显示并提供点击查看全文，同时记录适配降级事件。

FitBox 以 ResizeObserver 监听容器与内容，字体加载完成后重算；同帧内先统一测量再统一写入，避免布局抖动。隐藏容器跳过测量，activate / resize 时重算，suspend 停止观察，dispose 释放。缩放只影响呈现，不改变原始值和 titleText。

## 10. Overlay 与图片查看器

Overlay Runtime 统一管理 Tooltip、Popover、Modal、Drawer、Asset
Viewer、Page Dialog。局部提示可留在沙箱；需要超出页面边界的弹层由 Host
呈现。

普通查看器不创建 Page Runtime；Page Dialog 加载当前 Release
中授权页面，Context 默认局部继承，关闭即清理，最多一层。

Asset Viewer 使用 assetId
和资源版本，支持图片缩放、拖动、双击恢复、触摸手势、前后翻图、序号、标题、说明、关闭和全屏呈现。下载由权限决定。

图片采用缩略图、页面预览、放大规格、原始图的资源分层。超大图片通过切片方案按区域读取。加载失败可重试，切换时保留可用画面，解码受尺寸和内存预算约束。

弹层记录 ownerPageId、Display、Release、作用域和会话
ID。默认本屏打开；全墙打开需要 Show
授权。只同步资源、版本、索引及开关状态，缩放和拖动默认本地处理。

## 11. 视频播放

Media Runtime 管理播放会话；Asset Manager 管理资源及规格；Overlay
管理呈现；Scene/Show 决定节目推进。

  呈现方式   默认策略
  ---------- ----------------------------------
  页内视频   封面、点击播放、控件
  弹层视频   暂停自动切页，关闭后返回底页
  全屏节目   根据 cue 配置播完停留或继续
  背景视频   静音、循环、低优先级，按预算允许

同一会话记录媒体版本、进度、播放状态、音量和字幕。切换呈现方式优先保留播放实例；跨沙箱更换实例时先停原实例，再恢复状态。每个声音区域只指定一个主要声音输出，预监默认静音。

打开成功与实际播放成功分别反馈。自动播放受浏览器策略限制，失败显示明确播放按钮；无人值守设备在部署验收时验证播放策略。

下一条媒体有限预加载；重要节目可提前下载、校验并固定缓存。缓存设容量、淘汰和到期规则。正在播放资源及准备播出资源在会话内保护，空间不足时拒绝准备或按策略降级。

关闭、切页和销毁立即停止声音并释放无用资源。缓冲保留画面，失败显示封面及重试入口；媒体故障不触发整页重载。格式、分辨率和码率按设备实测选择。

## 12. 图片轮播与自定义堆叠

Gallery 由图片集合、Layout Adapter、Transition
Adapter、交互规则组成，复用 Asset Viewer 和资源加载服务。

  V1 内置布局   V1 内置切换
  ------------- --------------------
  平铺          滑动、淡入淡出
  层叠卡片      顶层退出、后方补位

Gallery Runtime 冻结 Layout Adapter、Transition
Adapter、暂停令牌和资源回收协议。V1
只内置并验收平铺滑动、淡入淡出和一种层叠布局；错位、扇形、中心聚焦、立体卡片及其他代码自定义布局或切换均作为扩展适配器，不属于
Phase B 必交范围，在 Phase E 按目标设备独立验收。

Layout
输入相对索引、容器尺寸和显示密度，输出位置、比例、角度、透明度及局部层级。Transition
负责从起始姿态到目标姿态的变化，不接管数据加载、计时或销毁。

自定义适配器限制在组件节点内运行，必须支持取消、resize 和
dispose。简单立体效果优先使用 CSS
变换；可见卡片数量和过渡节点数量有上限，透明隐藏不能替代资源回收。

配置包含：图片顺序、停留时间、循环、方向、布局、过渡、可见数量、裁切、箭头、指示器、暂停按钮、触摸滑动和点击放大。

点击后方卡片默认切到该张；点击当前卡片打开放大。拖动达到阈值后抑制点击。快速连点合并为最新目标，切换队列有界。组件层级局部隔离，溢出范围显式配置。

打开查看器暂停 Gallery 和
Scene。在查看器翻图后，关闭时回写当前索引并给予完整停留时间。悬停、键盘焦点和手动暂停分别保留暂停原因；适配减少动态效果设置。

默认预加载下一张，保留当前及转场必需图片。下一张解码完成再切换，超时跳过或占位；全部失败提供静态兜底。图片集合更新保留有效当前项，在切换边界应用新列表。

## 13. 暂停协调与单屏 Scene

Runtime 统一提供暂停令牌，按 scene、gallery、media、animation
分别作用。令牌记录所有者，关闭弹层只释放自己的令牌；页面销毁清理它拥有的令牌。

媒体播放暂停 Scene 自动计时，但不暂停自身；底页数据仍遵循 snapshot/live
策略。手动暂停不会因某个弹层关闭而解除。

Scene
定义页面顺序、方向、转场、停留时长、循环和数据模式。支持自动切页、键盘、触摸及演示器按键映射。

普通看板中轮播与页面停留独立计时；相册或视频专页可以等待媒体结束再推进，须同时定义最长等待和错误处理。循环媒体的结束条件为规定轮次或节目时长。

转场只涉及进入页和退出页。手动 Take
优先于自动计时，终止旧页弹层与媒体，再进行受控切换。

## 14. 多屏与同步协议

Wall 支持各屏独立、共享 Context、镜像内容。Player
本地渲染；同步命令、数据上下文和媒体时间基准。跨屏画面采用应用级近似同步，不承诺帧级锁定。

服务端保存 Show 权威状态和版本。命令包含
protocolVersion、commandId、showId、targetDisplays、sequence、controlEpoch、releaseId、issuedAt、executeAt
及 payload。

Player
校验控制权代次和序列号，重复命令幂等处理，返回接收、准备、执行或失败状态。为避免与能力契约的 Capability Command（commandId 以 cmd_ 开头）混淆，本节消息建议在工程契约中命名为 ShowControlMessage 并使用独立 ID 前缀；Take 等动作先经 Capability / Command 授权与确认，再由 Show 服务生成控制消息下发（拟定，待同步工程契约确认）。重连先取得权威状态快照，淘汰旧会话命令，再订阅增量。

Context
补丁由服务端排序，携带基础版本和新版本；冲突时重新同步，事件携带来源与关联
ID，防止循环联动。

多屏 Take 采用 Prepare → Ready → Execute。Prepare
完成发布包和必要资源检查；节目单默认在所有目标屏准备好后执行，也可显式允许部分屏降级。网络可能在执行阶段失败，因此不能宣称物理全屏原子切换；Director
必须显示部分成功并提供重试或回退。

Director
使用控制租约。时钟漂移和媒体位置定期测量；偏差超阈值时重新准备或校正。视频多屏只同步媒体版本、播放/暂停、进度和基准时间，不发送逐帧画面。

issuedAt /
executeAt、租约和授权有效期以服务端权威时间为准，客户端测量偏移并用单调时钟安排本地经过时长；业务日期归属按数据契约的业务时区。漂移容忍度写入
Profile。Take 中途租约变更、部分执行与 Context
冲突恢复的默认状态机仍须在同步工程契约中明确并验收，本次技术栈更新不视为这些异常协议已闭合。

## 15. 导播与现场保护

保存 → 草稿；构建发布 → 可播 Release；PVW → 预监；Take → PGM。

Director 显示各屏
Release、页面、在线状态、数据时间、播放状态和低频预览。预览采用 Player
状态回传及经权限允许的低频画面采集；无法采集时显示状态和资源预览，不假冒实时画面。Director
无需复制运行所有重型页面。

应急控制包括冻结、黑屏、LOGO
垫片和回退。冻结时暂停注册动画、媒体和数据应用；平台管理内容需遵守冻结协议。黑屏使用
Host 遮罩并停止声音，恢复时与权威状态对齐。

Player
缓存当前及上一稳定发布版本，以及明确允许落盘的最近可用数据。在线获知有效撤权后遮蔽或卸载受影响内容，关闭受限附件和声音并禁止复用受影响缓存；断网仅在已批准离线期限内使用缓存，到期隐藏，联网重新鉴权后恢复。要求即时在线核验的数据不允许离线展示。敏感数据落盘前须完成密钥托管、加密范围、期限和清理验收；不能仅写"加密"就开放。普通主页登出或切换身份同样终止受限嵌入会话，不复用其他主体结果。

## 16. 发布、依赖和回滚

Release 固定页面、组件、插件精确产物、构建依赖、Runtime 版本、模型 /
贴图 / 解码器、语言包 / 字体、其他资源版本、Query 定义、Dataset
契约及权限能力声明，附文件完整性清单和发布身份信息。

Studio 预览和 Release 构建负责将 TypeScript
等源码编译为可执行产物。Player 只加载已构建、已校验的 JavaScript
与静态资源，现场不编译 TypeScript 或其他源码。

锁定契约不等于冻结实时业务数据；实时数据按查询获取，汇报数据另绑定
snapshotId。用户权限始终按当前有效授权检查。

发布流程：构建 → Schema/依赖/能力检查 → 目标分辨率验证 → 设备预算验证 →
生成不可变包 → Player 下载校验 → Ready → PVW/Take。

Player
将新包完整写入后原子切换本地发布指针。下载不完整保持原版本。回滚前检查旧发布契约是否仍可用；数据源变化需保留兼容接口或对应快照，不能仅靠回滚前端解决。

可视化依赖投影覆盖 Dataset/Query Ref、组件、Page、Scene/Show、Release
与正在播出的
Display，用于构建检查和影响分析。它引用数据处理血缘、公共资源依赖和运行状态，但不成为这些事实的第二权威来源。修改数据口径、资源或组件前可查影响范围。

该可视化依赖投影同时覆盖主页
WorkspacePageVersion、嵌入页引用和插件包；升级需检查目标 Host、React /
渲染适配版本和语言资源兼容。后台治理可消费其受控投影进行全局查看，但不反向取得
Page / Release / PlaybackSession 的权威所有权。门户消费 Release
通过构建、预算与访问准入，使用主页版本发布流程；展播消费 Release 继续走
PVW / Take。两条发布流程不互相代替，均遵守当前授权、撤权及紧急禁用。

Release 同时记录 runtime 产物摘要、构建使用的 editor／build
版本和平台组合引用；配置组合与 Release
各自版本化，不以修改组合偷偷覆盖已发布内容。开发预览可在隔离环境受控重载；生产页面通过新
Release 和既有主页发布或 PVW／Take
流程升级。身份、查询和资产服务的当前授权始终生效。

升级分别检查编辑器、构建器、Runtime 和数据契约兼容；旧 Release
保留不保证数据库回退。安全禁用后的旧产物只能保留证据，不得自动回退运行。引用仍在的产物禁止物理删除。

### 16.1 长期维护与兼容

API、页面 SDK、组件契约、同步协议、发布清单和 Runtime
各自维护版本及支持范围。破坏性变更提供明确兼容窗口、迁移和弃用通知；构建和播放准备阶段拒绝不支持的组合，不静默降级为错误行为。旧
Release 的可用性同时取决于
Runtime、服务端契约及资源支持，不能仅靠保留静态文件保证永久运行。

新增交互协议或智能实现优先通过适配器接入，业务能力不依赖具体模型、提示词或协议。表现扩展继续使用组件、Layout、Transition
和 Media
契约；扩展边界不意味着可以忽略权限、生命周期或设备预算。不预建未知技术的空模块，也不承诺未来所有需求都无须局部重构。

升级采用兼容性测试、目标设备验收和新
Release；依赖锁定与可复现构建用于控制变化，不阻止持续安全维护。跨模块边界变更遵循总框架的决策、版本与迁移流程。

### 16.2 生成式 HTML 报表

用于分发、推送与存档的报表以 ReportDefinition 定义，每次生成不可变的 ReportInstance。在线报表随数据代次实时更新；生成式报表是数据快照，数据更新时生成新实例，不修改已生成实例。

ReportDefinition 引用已发布 Release 中的报表页面、Query 集合、筛选值、生成身份、触发方式、分发范围与保留期限。生成身份为登记的服务主体或明确的用户委托，按其当前有效权限取数；产物不随查看者权限变化，因此必须声明分发范围。

产物为自包含 HTML：模板、样式、已构建脚本、字体子集和数据快照 JSON 打包为单文件，图表在打开时由浏览器渲染。服务端只执行 Query 并写入快照，不使用无头浏览器渲染页面；PDF 或图片产物作为独立扩展任务，按部署预算另行验收。

触发方式为手动、定时与数据代次变化。代次触发在去抖窗口内合并；生成复用公共 JobRun / JobAttempt，设置并发与频率上限，同一定义同时只运行一个生成任务，运行期间新到代次至多排队一个。

ReportInstance 记录 snapshotId、Release、Query 契约版本、筛选值、各源数据水位、生成身份、生成时间与完整性摘要，按保留期限清理，仍被引用的实例不物理删除。

含受限数据的报表默认只分发链接，打开时按查看者鉴权；完整文件分发须在定义中显式允许并审计。生成完成作为领域事件 `visualization.report.generated`（拟定），经公共 Notification 与《Titanloom-集成与消息通道子方案》的 DeliveryRoute 发送至 webhook、机器人等目标，内容为摘要与受控链接，附件按分发策略决定，并受通道的最高数据级别限制（集成与消息通道 3.2）。撤权或紧急禁用后停止新生成，并按策略作废未到期链接；已发出的文件无法收回，分发策略界面须明示此限制。

## 17. 可观测性与恢复

记录查询延迟及错误、缓存命中、数据陈旧度、长任务、帧表现、资源加载、媒体缓冲、断线、发布、
Take 结果、报表生成与标题适配降级。日志以 Project、Release、Page、Display、sessionId 和
commandId 关联。

健康检查同时包含进程心跳和渲染进展。Player
启动器或设备管理服务负责失联重启；浏览器模式按可用能力降级。GPU
上下文丢失、组件错误、资源损坏分别恢复，优先缩小故障范围。

恢复顺序：局部重试 → 降低动画/画质/刷新频率 → 重建受影响组件 →
回退稳定内容 → 重启
Player。重试次数和间隔有上限，避免持续故障导致重启循环。

阶段 A 内部分为 A1 与 A2：A1 为 Project、Page、沙箱、Data SDK、响应式、静默刷新、中英文、字段筛选、报表模板绑定、FitBox 适配与标准图表页面（三个页面、两个 Dataset）；A2 为基础 3D 制作预览与渲染。A2 仍属首期范围，在 A1 出口门禁通过后交付。页面代码只在浏览器的隔离 Origin 中执行，不受服务端隔离宿主门禁 G-ISO 约束；但服务端构建只能使用平台内置构建器，**不得执行用户提供的构建脚本或构建插件**，需要时须先通过 G-ISO（ADR-016）。阶段 C 中的"主页卡片 / 看板 / 3D 嵌入"与门户方案阶段 B 的"固定 Release 嵌入"是同一项联合交付，由两方案共同验收，不得各自单方宣称完成。

## 19. 最终能力定义

平台以项目管理高代码页面，以受控 SDK
接入数据，以可扩展渲染适配器实现图表、地图及定制图形，以字段绑定实现筛选与联动，以模板绑定生成随数据更新的 HTML 报表，以三级规则与 FitBox 实现响应式，以
Overlay、Media、Gallery
