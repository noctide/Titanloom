## 1. 定位、目标与范围

后台治理中心负责公共规则的管理入口、身份授权治理、资源治理、能力接入、运行保障与审计恢复。各业务能力域继续拥有各自的业务事实、编辑器、规则和状态机；公共机制由其唯一公共
Owner
持有。后台是受控管理与观测入口，不是数据库任意编辑器，也不是第二个可视化制作中心，更不是第二套业务对象中心。

本文属于"公共平台能力"层；能力接入规范、插件与扩展、部署容量、ADR、第三方依赖治理属于公共平台规范层。总框架决定职责、依赖方向和权限语义；本文决定治理页面、治理投影、管理流程与治理验收；能力接入规范决定命令、委托、幂等和执行契约。冲突须记录并同步修订，不能由后台实现私自覆盖。

### 1.1 交付目标

1.  管理员能够知道资源归谁、谁可使用、依赖什么、当前是否健康。
2.  重要变更能够预览影响、按权限确认、跟踪生效和追溯证据。
3.  用户、Agent、自动化及管理页面复用服务端规则；管理入口不产生旁路。
4.  共享服务器的资源预算能在实际执行中落实，重任务不挤占全部交互资源。
5.  故障可定位、任务可核对、数据可恢复；不把接收成功当作业务完成。
6.  前台已有图形能力通过组件复用接入后台，后台关系来自权威对象与执行记录。

### 3.1 技术实现基线

采用总框架既定 React、TypeScript、Ant Design、React Router、TanStack
Query；局部关系图与运行图优先复用已选 React Flow
的适配组件。图布局、关系查询和业务状态独立于组件库，不将库内部节点结构作为平台数据库模型。本文不新增前端框架或图数据库依赖。

服务端采用既定 Python
3.12.10、FastAPI、PostgreSQL，模块化单体起步。公共管理服务按身份、授权、目录、配置、配额、审计划分内部接口；无需为每个模块单独部署微服务。重任务进入既有
JobRun 和隔离执行器。标准部署才按总框架引入 RabbitMQ／Celery。

### 3.2 三类数据通路

  管理观测                队列、任务状态、策略判定、心跳、资源依赖   对应管理服务与监控适配器，不依赖业务

  业务分析                工时、考勤指标、稽查分析等                 已发布
                                                                     Dataset／Query，继续遵守统一数据出口
  ---------------------------------------------------------------------------------------------------------

管理元数据通路不是业务数据查询后门。显示失败样本、日志中的业务字段、SQL
内容、源文件名等，须有相应访问资格并做投影。健康探针不返回业务数据或凭据。

治理投影统一遵循"可重建、可标陈旧、不可反向夺权"：ManagedResourceRef、DependencyEdge、DomainRunRef、DomainAlertRef、搜索索引和图节点都必须保留
source / sourceVersion / observedAt
等来源证据；投影缺失或过期只能降低治理视图能力，不能据此改写领域事实、放行破坏性操作或宣称对象不存在。

### 3.3 故障依赖

管理查询投影故障时，单个对象可回查权威服务；标记"关系视图不可用"，不假装无依赖。业务数据处理故障不影响任务和告警的管理状态读取。PostgreSQL
或认证服务整体不可用时，不能承诺后台可用；基础设施另保留独立的健康告警和运维恢复路径。后台不依赖
Agent 才能完成核心管理。

## 4. 身份、角色与权限设计

### 4.1 管理角色模板

下表为默认职责包，不是硬编码角色判断。实际以
capabilityId、资源范围、条件、显式拒绝及有效期裁决。

  ---------------------------------------------------------------------------------------------------
  模板                    默认职责                                   必须另授或不授予
  ----------------------- ------------------------------------------ --------------------------------
  平台配置管理员          非敏感平台配置、导航、空间生命周期         最高授权、业务内容、凭据读取

  平台最高授权管理员      授权上限、Agent 一门、委托授予边界         业务数据读取和业务审批仍独立

  运维管理员              执行器、预算、告警、备份操作、受控维护     任意业务修改、全部日志明文

  安全审计员              获准范围的审计与授权证据                   修改配置、确认自己的高影响操作

  空间／项目管理员        范围成员与设置、获准的角色绑定和二门启用   超出自身可授予范围的授权

初始部署通过受控引导创建首位授权管理员，建立个人可追溯账户后关闭引导凭证。不得预置长期共享超级账号。最后一名可用最高授权管理员的撤销须有替代接管路径并校验，避免平台失管。

应急访问采用单独登记、限时、限范围、事后复核的运维流程；它不允许模型获取密钥、不取消
On-air
等硬约束。平台故障导致无法在线授权时，使用企业既有基础设施恢复流程，不伪装成平台普通授权。

### 4.2 人员主数据与账户

Account／Principal 表示登录或执行主体，Person 表示业务人员；Employment
保留任职有效期；SourceIdentity
保存外部来源映射。自然人、工号、用户名不可混为主键。

人员与部门有权威来源时默认同步管理。人工更正形成版本化覆盖或待核对记录，不能下次同步静默覆盖。重名、换工号、离职再入职、部门调整进入证据核对流程。历史业务记录保留当时的组织与映射版本。

停用账户撤销会话、检查相关委托、阻止新交互；业务历史不删除。服务身份离开责任人时进入交接或停用流程，不因负责人离职使自动化悄悄成为无主任务。更换任务执行身份必须重新授权，不能直接套用新负责人的全部权限。

### 4.3 授权页面与判定链

授权编辑按照"主体／组---资源范围---能力---数据条件---有效期"展示。角色模板版本与成员绑定分别维护；复制角色不复制成员、数据授权或
Agent 开关。新增能力默认不进入旧模板。

权限检查使用真实服务端裁决逻辑，以主体、调用类型、目标、动作和必要上下文为输入，输出
allow／deny、策略版本、判定时间、适用约束及允许公开的原因。它不执行目标动作，也不保证未来仍允许。

``` mermaid
flowchart TD
    I["身份、调用端与委托"] --> B["基础授权与资源归属"]
    B --> T{"Agent 调用？"}
    T -->|是| A["三道门与来源限制"]
    T -->|否| D["数据与附件范围"]
    A --> D
    D --> C["版本、状态、确认、租约与预算"]
```

任一检查失败可立即拒绝，图示不表示必须继续读取全部敏感信息。检查他人权限需要独立的权限诊断资格；对不可见对象不返回名称、数量或存在性。结果导出属于单独能力。

### 4.4 Agent 三道门管理

  ----------------------------------------------------------------------------------------------
  层次                    管理页面                行为
  ----------------------- ----------------------- ----------------------------------------------
  平台资格                Agent 与模型／能力资格  最高授权管理员设定能力策略上限及模型输入边界

  范围启用                空间／项目设置          具备业务能力和策略管理权的人在上限内启用

  资源准入                资源详情／权限          具备资源准入管理权的人决定是否允许进入
  ----------------------------------------------------------------------------------------------

页面展示配置值与实际生效值。父级关闭时，子级即使保存了开启记录也显示无效及原因。平台一门收回后再次开启，旧二门须重新显式启用。Agent
不得通过角色修改、成员变更、委托创建等间接路径扩展自身权限。

撤权采用权威策略版本更新、缓存失效事件、队列执行前复查、运行检查点及交付复查。界面分别显示"已记录""传播中""已达到登记生效边界"；不能只因通知发出便宣称所有节点已撤权。离线内容和已交付数据的限制沿用总框架。

### 5.3 PostgreSQL 约束与索引

按模块划分
schema／表及数据库角色，不允许跨模块任意写入。必要唯一约束包括：角色版本号、配置键与范围内修订号、命令幂等作用域、事件消费
ID、依赖边的来源版本与两端引用。

列表索引优先覆盖
workspaceId、resourceType、state、updatedAt、id；运行查询覆盖
scope、state、createdAt；依赖同时建立来源与目标索引；审计按时间和范围检索，增长后再分区。分页稳定排序包含
ID，禁止无边界全量读取。

跨模块投影使用事务事件／outbox、幂等消费、来源版本比较和定期对账。乱序事件不得让新状态被旧状态覆盖；删除用明确
tombstone。投影可以重建，授权裁决与破坏性操作不依赖可能过期的投影。

对象详情按适用性显示：概览、配置、权限、依赖、版本、运行、审计。顶部显示稳定

首期 zh-CN／en-US，使用统一 messageKey
与参数；ID、枚举、能力名不翻译。长名称换行或展开，不挤压操作按钮。时间戳显示当前显示时区和原始
UTC
查询入口；业务日历与业务时区另列，不因显示语言改变。关键确认文案缺译阻止该语言发布。

## 7. 配置与变更生命周期

### 7.1 配置分类与继承

  ---------------------------------------------------------------------------------------------------
  类型                    举例                       合并与生效
  ----------------------- -------------------------- ------------------------------------------------
  展示偏好                个人语言、列表列宽         最近范围覆盖，保存后即时生效

  业务公共配置            通知模板、默认主页、语言包 不可变发布版本，引用方按契约更新

  资源上限                并发、内存、输出体积       上级总预算约束，下级不得扩权；按准入与预留核算

  安全策略                Agent 资格、模型边界、授权 沿用总框架求交与显式拒绝规则，不用普通覆盖

  部署配置                存储挂载、数据库连接设施   受控部署变更，部分只读展示，不通过普通 UI 任意改

  秘密                    数据源密码、模型凭据       只保存 SecretRef，独立轮换，页面不回显原文
  ---------------------------------------------------------------------------------------------------

每个 ConfigDefinition
明确允许层级、Schema、默认值、是否可继承、合并算法、验证器、依赖、生效方式和回退限制。任意
JSON 编辑只有在受控 Schema 和权限下提供；不能成为执行脚本入口。

### 7.2 修订与激活分开

ConfigRevision 使用
draft、validated、published、superseded、withdrawn；发布后内容不可变。Activation
使用
pending、applying、effective、partial、failed。修订发布不代表所有目标已应用。

``` mermaid
flowchart TD
    D["编辑草稿与基线版本"] --> V{"Schema、权限与依赖校验"}
    V -->|失败| D
    V -->|通过| P["差异与影响预览"]
    P --> C{"需要确认或审批？"}
    C -->|需要| H["具体人工确认或既有审批"]
    C -->|不需要| S["准备并提交命令"]
    H --> S
    S --> A["发布修订并跟踪激活"]
    A --> R{"目标均应用？"}
    R -->|是| E["生效"]
    R -->|否| F["部分生效或失败，核对处置"]
```

普通低影响配置由客户端自动连续准备和提交，不额外要求用户点击两次。对高影响管理动作，确认须绑定具体版本、参数与范围；若企业要求四眼审批，发起人与批准人分离并复用审批设施，不另造通用审批引擎。

### 7.3 并发、事务与回退

编辑携带
expectedResourceVersion；冲突返回新版本及受权差异，用户合并后重提，禁止最后写入覆盖。发布在本库事务内写修订、审计、命令接收和
outbox。跨节点激活可最终一致，记录每个目标已应用版本、失败和重试时间。

安全收紧不能因某节点未确认就回退为旧的宽权限；节点状态不可信时阻断相关受限动作。配置恢复旧内容也要创建新修订，并重新校验当前依赖与权限。已经发生的业务写入、外部通知及外部副作用不由配置回退撤销。

### 7.4 删除、停用与维护

  动作       语义
  ---------- ----------------------------------------------
  归档       从日常使用入口移出，保留事实和引用
  停止新用   禁止新建引用或新任务，旧使用按明确策略继续
  停止服务   停止既有服务能力，列出受影响对象
  紧急禁用   优先阻断后续受限操作与交付，记录原因和影响
  物理清除   保留期满足、无有效引用、无运行占用后清除字节

删除前依赖图用于提示；提交时调用权威依赖检查并防止并发新增引用。依赖不完整时阻止破坏性清除或进入人工核对，不能把"查不到"解释为"无依赖"。维护模式按服务和范围开启，明确读、写、新任务及现有任务行为，不默认全平台停机。

### 7.5 业务参数

业务参数是各业务域登记、可由业务管理员调整的单值配置：数值、开关、选项或名单，例如签到宽限时间、月度加班额度上限、导入单批最大行数、看板最小刷新间隔。全平台的业务参数只在平台管理的"业务参数"页集中查看和修改，不在各领域另设参数页（ADR-022）。

  -------------------------------------------------------------------------------------------------------
  内容                        归属与规则
  --------------------------- ---------------------------------------------------------------------------
  参数定义                    由所属领域以 ConfigDefinition（类别为业务参数）登记：键、LocalizedText
                              名称与说明、类型、允许范围、默认值、允许覆盖的层级、验证器、生效方式、敏感级别

  参数值、修订与激活          配置服务按 7.2 管理：草稿、校验、影响预览、发布、按目标跟踪生效；
                              发布后的修订不可变，回退也创建新修订

  影响预览                    由所属领域的能力计算（例如受影响人数、是否涉及已发布期间），后台只展示

  读取                        领域在业务事务中读取当时生效的值，并在结果中记录所用修订
  -------------------------------------------------------------------------------------------------------

键使用领域命名空间（如 `attendance.checkin.graceMinutes`），作为稳定 ID 不翻译。覆盖层级只能是定义声明允许的层级（平台、空间、项目，或定义声明的组织单元），合并按 7.1 处理，下级不能突破定义的允许范围。修改可立即生效或指定生效时间；默认不追溯已发布的期间或结果，需要重算历史时由所属领域单独发起更正命令。

界线：能用一格填写的放这里；需要画布、编辑器或结构化版本的"定义"留在各自领域，包括班次与规则集、表单设计、流水线、看板与页面、流程定义。领域页面可只读显示当前值，并链接到本页对应参数。

页面：按领域分组的参数列表，可按领域、适用范围和"只看已改动"筛选；详情显示定义、当前值与各层覆盖、待发布修改、影响预览和修改历史。修改走 `titanloom.admin.config.publish` 的业务参数类别授权；高影响参数由定义标注，发布前须确认影响。Agent 可以查找参数并准备修改草稿，发布须人工确认。

## 9. 任务、执行器与资源治理

### 9.1 任务事实与状态

复用《Titanloom-平台能力契约与Agent接入规范.md》V1.0 第 8.3 节的
JobRun／JobAttempt
设计状态及领域运行引用，不另造后台任务状态机。界面将其分组为等待、运行、取消申请、待核对和终态；精确枚举以本规范第
8.3 节为设计基线，待工程 Schema 与状态映射测试通过后方可称已发布契约。

接收记录、执行完成、质量通过、正式发布分别展示。Worker
失联不直接判为未执行；对外写入结果不确定时保留待核对，禁止一键重新运行造成重复副作用。日志时间线关联
requestId、commandId、invocationId、jobId、attemptId、domainRunRef 与
agentTaskId。

### 9.2 控制动作

  --------------------------------------------------------------------------------------------------------
  动作                                条件与结果
  ----------------------------------- --------------------------------------------------------------------
  取消                                契约支持；记录请求后协作停止，必要时终止受限进程，核对已提交副作用

  自动重试                            同一逻辑 Job 的安全 attempt，保留幂等与预算

  重新运行                            新业务意图和新命令，固定输入、范围、版本，显示重复影响

  从检查点恢复                        领域确认检查点有效、依赖兼容和剩余授权

  暂停队列领取                        停止新领取，不谎称现有任务已暂停

  排空执行器                          不接新任务，等待或受控结束既有任务，回收租约和临时资源

  人工核对                            记录证据与结论，调用领域确认或补偿能力，不直接改数据库状态
  --------------------------------------------------------------------------------------------------------

### 9.3 配额与准入

配额分平台总池、任务类别池、空间份额和单次上限；分别管理
CPU、内存、线程、数据库连接、查询时间、并发、临时磁盘、输出、模型调用和重试。内存等瞬时用量采用预留和回收；存储等累计量采用持久计量；不可把不同维度相加成一个不透明分数。

准入原子核对可用预算并建立
Reservation，防止两个调度器同时超卖。租约过期先核对进程是否仍运行再回收额度，不能因心跳丢失立刻释放并启动更多任务。实际
OS 资源约束和数据库超时、连接池限制承担最终执行，不靠应用自报用量。

降低额度默认约束新准入；现有任务超过新限额时显示超额，并按预先声明的排空或终止规则处理。紧急停止独立授权。公平调度按空间和类别避免大批量任务长期饿死交互任务；所有队列有上限及最大等待期，超限明确拒绝或排队。

共享服务器的物理总内存不等于平台预算。部署前由运维登记实际分配额度，为
OS、数据库、API
和其他业务留出空间。小型验证环境采用更低并发并离线构建前端；不能用验证环境成绩声称企业生产容量已通过。

## 10. 能力、插件、Agent 与连接管理

### 10.1 能力与插件

能力目录沿用 draft／active／deprecated／disabled／retired
状态。登记与启用页面显示能力 ID、契约版本、归属模块、输入输出
Schema、作用范围、影响等级、超时、幂等、验证器和实现摘要。active
不自动授予人或 Agent 权限。

插件分别显示包版本、部署安装、范围启用和实例引用。包签名、信任发布者、离线依赖、贡献类型宿主契约和运行预算通过检查后才能安装；安装不代表范围启用。升级固定新版本、生成影响清单、试运行与迁移计划，不将所有引用替换成
latest。

停止新用、紧急禁用、卸载和清除产物分开。旧 Release
固定版本不能绕过紧急安全禁用；有运行或发布依赖的字节不能直接删除。业务事实保留与插件卸载分开。首期管理既定组件、解析器、转换算子、工具、模型适配链路，未验收宿主显示不可启用。

### 10.1.1 服务绑定、组合及运行实例

沿用总框架第 8.6 节对象，后台不另造运行内核。新增
ServiceContract／ServiceBinding、DeploymentCompositionVersion、RuntimeInstance
和 UpgradePlan
的管理视图。部署组合显示精确插件版本、摘要、提供与依赖服务、宿主兼容、必需能力和预算；生效配置能够解释每项绑定来源。平台部署管理员发布组合，空间／项目管理员只在获准范围配置，不能替换全局治理服务。

安装、启用、服务就绪、业务实例及发布引用分别展示。注册失败、依赖缺失、冲突、循环、启动失败与排空超时给出诊断及影响范围。单提供方服务拒绝歧义绑定；身份授权必需服务失效时不提供放行回退。后台使用相同授权链，管理图形不是越权旁路。

UpgradePlan
保存旧／新组合、配置差异、依赖影响、数据迁移、在途任务策略、兼容验证、恢复点及回退限制。先停止新准入，再排空或经授权终止，完成迁移和健康检查后激活；记录部分失败，不把发布完成当作激活完成。不可逆迁移须有明确恢复或前向修复路径。插件卸载不删除业务事实，不撤销外部副作用。

清单登记上游来源、精确提交或版本、许可证、修改说明和第三方声明；实际交付生成
SBOM。签名证明产物来源完整性，不等于许可证合规或代码安全认证。

### 10.2 模型与 Agent

ModelEndpoint
登记批准的部署边界、模型标识、适配器版本、责任人、超时、并发、输入类别、凭据引用和可用状态。运行端登记身份与用途，委托限定资源、能力和期限，不继承管理员会话。

停用模型阻止新的模型调用并跟踪在途请求；已获授权的确定性任务能否继续按既有契约判断，不一律取消全部
Job。后台展示成本或用量为已知计量／估算，不把估算当账单事实。模型输入预览只展示操作者有权查看的受控摘要。

### 10.3 连接与凭据

数据源实例的业务字段由数据处理模块维护，后台维护批准目标、使用资格、SecretRef、轮换和健康摘要。凭据创建后不回显，管理员可替换但不因此能读取原文；日志、命令摘要及导出均只记录引用。

连接测试使用受控执行器、批准网络目标、短超时和最小权限。解析目标、跳转和地址变化仍须符合出网策略，禁止以测试接口访问任意内网地址或本机文件。测试成功只说明当时连通，不代表可读取全部数据或永久可用。

轮换创建新凭据版本，验证后切换新使用方；旧任务在声明窗口内处理，紧急撤销优先安全阻断。失败显示各消费者状态，不静默切回被撤销凭据。

## 11. 资产、门户与通知治理

### 11.1 资产生命周期

资产状态覆盖上传中、检查中、可用、隔离、撤回、待清理及已清理的语义，精确枚举归
Asset
契约。后台可查看用量、派生任务和授权依赖；无内容权限的运维人员仅见必要大小、状态和技术
ID。

清理须核对引用、保留期、活动任务、发布版本、恢复需要与保留锁。内容去重不合并授权；相同字节被多个业务使用仍各自校验关联。对孤立文件采用宽限期、复核和幂等清理，上传事务尚未完成不判定为孤儿。

短期资产访问和强撤权继续遵守接入规范。图片、视频、导出与日志包作为受控产物，不能通过管理图截图或导出变成公开文件。

### 11.2 门户管理

Shell / 门户拥有默认入口、导航、公共主页模板、WorkspacePage /
WorkspacePageVersion 及其发布语义；后台只提供这些 Shell Capability
的受控治理入口、权限/配置视图和生效跟踪，不复制主页定义。复杂卡片、看板、3D
在可视化中心制作并引用固定 Release。WorkspacePageVersion 与可视化
Release 分别管理，公共主页发布不触发 Take，不向 On-air 热推代码。

个人布局不覆盖公共主页，公共主页编辑与发布独立授权。页面预览按预览者身份，Player
使用独立展示身份；作者权限不转授给访问者。

门户管理入口同时承载快捷导航、首页卡片可见范围和首页宣传轮播排期（Shell 6.6、6.7、11.2）的受控配置与生效跟踪，对象仍归 Shell。

### 11.3 通知与待办

通知渠道、模板、收件范围和限频由公共设施管理；业务待办的完成状态由所属模块管理。告警通知包含必要摘要和受控详情链接，不在邮件或消息中嵌入原始凭据、业务明细和长效附件链接。

投递失败与业务失败分开。重试有上限和去重键，重复投递不重复创建业务待办。测试通知只能发送至操作者获准的测试接收范围。

外部通道（Webhook、机器人接口等）与入站端点的统一可视化配置入口为"集成中心"，页面由本中心承载，对象与规则归《Titanloom-集成与消息通道子方案》；本中心只提供受控入口与生效跟踪，不复制通道、路由或端点定义。Webhook 地址按密钥处理，使用 SecretRef，不回显；SecretRef 最小集与出网守卫随 M4 提前交付。

## 12. 监控、告警、审计与恢复

### 12.1 观测与告警

最小部署采集服务可用、API
延迟与错误、数据库连接占用、队列积压与最老等待、执行器心跳、磁盘、临时空间、备份结果、投影水位。增强监控适配器按需要增加，不作为最小部署硬依赖。

公共监控告警设施是"平台基础设施与公共运行机制告警"的权威来源；各业务领域仍可拥有具有业务语义的异常/告警对象，例如
AttendanceAlert。后台通过 DomainAlertRef
聚合其受控摘要，不复制领域状态机，也不要求所有业务异常改造成
PlatformAlertInstance。领域状态、领域告警、平台运行告警与 Notification
分别管理：Notification
静默/已读不改变告警或领域状态；PlatformAlertInstance 的 acknowledged /
resolved 也不自动证明业务问题已修复。PlatformAlertRule
保存范围、窗口、阈值、恢复条件、严重度、去重键、路由与维护静默。抖动抑制和合并在规则内明确，静默不删除事件。日志、指标和审计分别保留预算，不把高频指标逐条写成审计。

平台运行概况：各领域按周期把受控、聚合的用量与运行指标（如活跃人数、表单提交数、运行次数与失败数、存储用量）写入"平台运行"数据集，由数据处理按 Dataset / Query 汇总，首页的"平台运行概况"Studio 卡片展示（Shell 6.7）。该数据集只含聚合数，不含业务明细和个人行为轨迹；它是运营展示，不是计费、考核或审计事实，也不替代本节的监控与告警。

### 12.2 审计

管理写入审计至少记录
eventId、发生／接收时间、principalId、executorId、调用端、委托、能力与版本、目标、前后值摘要、原因、策略版本、确认、commandId、jobId、结果和证据。秘密与无必要业务数据不写入摘要。

本库关键写入与必要审计／outbox
同事务落地；审计持久化失败时阻止该关键写入。外部副作用以执行意图和后续对账证据串联，不声称数据库审计与外部动作原子完成。

普通管理员无修改历史审计资格。限制数据库与存储的写入权限、定期归档并校验摘要；需要更强防篡改时另用批准的独立归档设施。不能仅靠"追加表"宣称数据库超级管理员也无法篡改。查看及导出审计同样记录并受权限约束。

### 12.3 备份与恢复

备份覆盖
PostgreSQL、资产及发布产物、契约与迁移、配置、必要凭据密文及对应密钥恢复材料。密钥材料独立受控保存，不能只有密文没有可恢复密钥。BackupSet
记录一致性时间／水位、数据库恢复点、资产版本清单、摘要、保留策略、验证结果与恢复工具版本。

数据库与文件不假定同一事务快照；借助不可变资产版本、备份清单、写入窗口协调及必要日志恢复保证引用可核对。未验证的备份显示"已生成、未验证"，不能显示"可恢复"。

恢复先到隔离目标：校验备份与密钥 → 恢复数据库和资产 → 校验引用及契约 →
禁止调度、Agent、通知和外部写入 → 验证核心业务与权限 →
批准切换。恢复环境默认不发送真实通知，不重放外部副作用。

正式切换前重新核对备份后撤销的账户、委托与安全禁用，轮换失效会话和必要密钥，避免恢复旧库复活已撤销权限。恢复过程中使用范围锁／维护状态，防止两个写入环境同时成为权威。

RPO、RTO、频率、保留期限和异地范围由部署资源与业务要求确定，上线前必须有值并演练。代码回退、配置回退、业务补偿、全库恢复分别授权。平台故障时恢复由独立运维执行路径完成，事后回填验证证据。

### 13.3 写命令与错误

管理写入使用既有 Capability / Command 的 prepare、confirm、submit
协议；传 expectedResourceVersion
和精确输入版本，幂等作用域、确认消费及响应丢失恢复沿用接入规范。Command
表达意图，DomainEvent 表达已发生事实；事件、通知和审计均不是旁路写
API。配置激活是领域结果，必要时可关联 JobRun 执行；不把 command
accepted、Job succeeded 或 Notification delivered 标成 effective。

错误统一返回稳定 code、messageKey、受控 details、requestId
及可恢复类别。建议覆盖版本冲突、依赖阻塞、范围拒绝、预算不足、投影陈旧、部分激活、待核对和目标不可用；具体错误码在统一契约中登记。重试不能自动扩大预算或更换命令意图。

### 13.4 事件与推送

事件至少包括资源版本变化、引用变化、角色与授权变化、委托撤销、配置发布与激活、任务状态、执行器心跳、资产撤回、插件禁用及告警变化。事件使用平台统一事件信封：eventId、type、schemaVersion、source、scope、subject、sourceVersion、occurredAt、recordedAt 和 correlationId，增量同步另带 changeSeq，更正事件带 correctionOf，自动化与联动产生的事件带 causationId，并可带来源 Run / 步骤引用 originRunRef（可选）（字段定义见 titanloom-contracts 的 outbox-event）。

WebSocket
复用既有推送能力，通知变更及受控摘要；查询接口仍是权威。订阅建立与续期校验权限，撤权关闭相关订阅并清理受限客户端缓存；断连后
cursor 补齐，超出保留窗口重新拉取，不让历史事件绕过当前权限。

## 14. 安全边界与操作可靠性

1.  管理页面不继承数据库管理员权限；服务端每次验证动作、范围、字段与状态。
2.  凭据、个人数据、审计内容、源码和业务样本分别授权，不能以"运维需要"默认全可见。
3.  Cookie 写请求沿用 CSRF 防护；任意第三方 UI 使用隔离
    Origin，后台管理组件不能动态加载未批准远程脚本。
4.  文件、连接和探针仅访问批准目标；用户输入不得成为系统路径、命令或无边界网络请求。
5.  高影响操作固定目标集合、版本和摘要；批量操作提交时重新检查，过期预览不放行。
6.  需要即时权限校验的管理动作在授权服务不可用时拒绝，不能回退为允许；普通非敏感观测可展示明确过期的缓存。
7.  临时文件、图快照、诊断包和导出有容量、期限与责任人，过期回收失败可观察。
8.  初期不引入任意用户编写的权限判定脚本；扩展必须使用受控表达与验证器。
9.  生产管理配置支持版本追溯，应用部署和数据库迁移走受控发布；不能把后台按钮变成未经审查的软件安装器。

## 15. 典型管理闭环

### 15.1 新建安全稽查项目

1.  创建空间／项目，设置负责人和预算，生成稳定 ID。
2.  将稽查员组绑定到项目范围角色，独立授予清单读取、问题编辑、附件预览等能力。
3.  在业务中心配置问题表单或外部 Excel
    接入；后台不代建另一套问题记录表。
4.  外部 Excel 通过数据处理接入，图片通过 Asset 关联问题 ID，发布 Query
    和看板。
5.  依赖图显示资源关系，权限检查证明项目成员资格不会自动开放所有图片下载。
6.  如需 Agent，人工逐层配置三道门及模型输入范围；保持默认关闭直到验收。

### 15.2 数据任务失败处置

总览告警进入运行图 → 查看该次固定版本与失败 Attempt →
判断资源超限、输入质量或外部结果不确定 → 使用领域允许的重试、恢复或核对
→ 验证产物与发布结果 → 关闭告警或继续处置。不得因 Job
完成就自动宣称业务数据已正式发布。

### 15.3 连接轮换与停用

查看依赖 → 固定受影响实例与版本 → 测试新凭据引用 →
按批切换并记录实际应用 → 核对排队和运行任务 →
撤销旧凭据。若为泄露处置，紧急撤销先行，随后恢复受影响业务，不以平滑切换为由延迟安全禁用。

### 15.4 人员离职交接

停用交互账户及会话 → 核对组绑定与委托 → 转移资源责任人 →
为需保留的自动化重新建立最小服务授权 → 校验无无主任务与有效旧令牌 →
留存历史事实。历史工时和审批签名不改成接任者。

## 16. 性能、部署与上线参数

### 16.1 参数登记

以下每项必须在部署清单登记实际值及验证证据，缺失时不能宣称对应能力已验收。

  ------------------------------------------------------------------------------------------------------
  参数组                              必需项目
  ----------------------------------- ------------------------------------------------------------------
  资源                                平台 CPU／内存／磁盘、数据库连接、各类 Worker 并发与线程、单 Job
                                      上限

  权限                                策略缓存最大陈旧期限、运行检查间隔、委托／令牌期限、离线授权范围

  交互                                列表页上限、图节点／边／深度上限、接口时间和字节预算

  观测                                心跳周期、失联阈值、图陈旧阈值、告警窗口、投影最大延迟

  保留                                审计、日志、临时资产、幂等记录、事件补发窗口和备份期限

  恢复                                RPO、RTO、一致性检查范围、演练频率与切换条件
  ------------------------------------------------------------------------------------------------------

### 16.2 建议验收负载与目标

使用合成数据初始建立 10 个空间、1 万管理资源、5 万依赖边、10
万任务历史和 100 万审计事件；并发管理会话先测
20。该夹具用于验证分页、索引、权限隔离与增长趋势，不代表产品规模上限。企业数据不传入个人验证环境。

在登记的标准内网配额与目标浏览器上，建议初始目标：有界列表和对象详情 p95
不超过 1 秒；100 节点／200 边图首次可交互 p95 不超过 2
秒；可见运行状态在 5
秒内更新。测试前可按资源条件修订并冻结，报告必须注明服务端／端到端口径、网络、设备、样本量和冷热缓存，不能事后变更目标掩盖失败。

安全策略传播期限另行严格登记，不沿用 5 秒 UI
刷新指标。运行图在硬上限、连续展开与重复挂载下验证主线程阻塞和内存趋势；后台长期打开不得无限累计日志、节点和订阅。

  A02                     跨空间更改 URL           服务端以真实归属拒绝，不泄露其他空间存在性
                          或请求范围

  A04                     Agent 任一道门关闭       搜索、图、日志、运行、模型交付均不能旁路

  A05                     一门撤销后重开           原二门不自动复活，人工权限不被 Agent 开关误伤

  A06                     排队与运行中撤权         达到登记边界，后续操作与交付受检，已提交事实正确保留

  A07                     两人并发编辑配置         旧版本提交冲突，不覆盖新版本

  A08                     确认后参数或目标改变     原确认无效，重新准备；同命令重复提交只有一个逻辑接收

  A09                     配置部分应用失败         显示目标级实际状态，安全收紧不回退成宽权限

  A10                     依赖投影过期或缺失       删除不能误放行；权威检查发现新引用并阻止破坏

  A11                     历史运行与新 DAG 不同    显示历史固定版本，不以最新定义冒充

  A12                     Worker                   进入核对，不盲目重试；证据可追踪
                          失联且外部写入未知       

  A13                     取消长计算               申请与完成分开，进程和临时资源回收，已提交副作用说明准确

  A14                     两个调度者竞争预算       预留一致，无超卖；租约失联不重复放行仍运行任务

  A15                     停用仍被引用的插件       普通卸载拒绝；紧急禁用受影响内容按规则降级

  A16                     图超预算与循环关系       截断明确，去重限深，分页后仍鉴权，界面不冻结

  A17                     推送断连与权限变更       补事件或重拉，隐藏受限缓存，不把旧快照当当前事实

  A18                     连接测试与凭据轮换       仅批准目标、无秘密回显，失败消费者可见且可处置

  A21                     数据库与资产恢复         引用完整、密钥可用、旧撤权不复活、外部写入默认停用

  A22                     模型／业务 ETL 不可用    核心人工管理及相应运行观测仍可用；自身底座故障如实展示

  A23                     中英文与时区切换         确认含义一致，ID 不变，业务期间和授权期限不漂移

  A24                     低配与标准部署           无虚构组件，资源约束真实生效，容量结果分别报告

## 18. 实施顺序与工程拆解

  -------------------------------------------------------------------------------------------------------------------------------
  阶段                    工作包                                                     完成门槛
  ----------------------- ---------------------------------------------------------- --------------------------------------------
  P0 契约与模型           角色职责、对象归属、能力映射、配置语义、图契约、参数清单   与总框架和接入规范一致，无重复权威对象

  P1 最小管理闭环         身份与空间、角色绑定、资源目录、任务读取、基本配额与审计   创建空间→授权→运行→排障→受控处置可演示

  P2 治理与图形           局部依赖、运行图、判定链、简版拓扑、配置激活与撤权         陈旧状态、并发变更、权限隐藏和依赖阻塞通过

  P3 上线保障             插件／Agent 管理、凭据轮换、资产治理、告警、备份恢复       首期适用的 A01---A24 完成并留证

  P4 按需扩展             多节点观测、大规模聚合、更细血缘与额外宿主                 实际负载与业务需求支持，独立预算及验收
  -------------------------------------------------------------------------------------------------------------------------------

与《Titanloom-实施路线与首期工程基线》的对应：P0 属 M0，P1 属 M1，P2 与 P3 属 M4（SecretRef 最小集与出网守卫随 M4 的集成与消息通道一同交付），P4 为条件阶段。

P0---P3
是首期分步实现顺序，不表示未完成恢复或授权验收就可生产上线。开发过程中可用
P1 提前联调，但上线必须关闭全部适用门禁。

工程产物包括：数据库迁移、唯一约束与索引；能力描述符与 OpenAPI
Schema；前端路由和页面状态规范；事件与订阅协议；执行器配额设施；集成测试；部署参数模板；备份恢复和应急手册。精确
Schema 存工程仓库，本文维护语义，不复制多份相互漂移的完整接口定义。

## 19. 总框架同步关系

后台治理中心与现行总框架、能力接入规范共同遵循已经冻结的对象所有权、调用、状态和跨域边界。总框架定义边界，本文定义治理页面、可重建治理投影和操作闭环；能力接入规范继续定义调用契约。插件运行时对象以现行插件与扩展规范及总框架公共边界为依据。

新增验收：必需治理服务缺失时拒绝准入；跨空间绑定不能串凭据；冲突／循环依赖拒绝启动；升级失败能定位实际激活版本；在途任务排空和精确版本重试；不可逆数据迁移不能伪装成一键回退；紧急禁用传播到旧
Release；Agent 候选运行时退出不影响人工业务。上述首期适用门禁与
A01---A24 一并验收，不因"插件管理在 P3"而延后基础契约设计。

  ------------------------------------------------------------------------------------
  决策                                原因与影响

                                      ETL
