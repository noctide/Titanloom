# 合成数据 · 人设表（M0-06 第一部分）

> 工作包：GitHub Issue #29「M0-06 合成数据生成器与人设表」。
> 规格来源：Issue #29 评论中的「人设表规格」（与 `_启动指令/roster-spec.md` 一致），2026-10-16 从平台管理「人和权限」花名册抽取。
> 本次只做人设表；工时、考勤、基表样本待后端表结构定稿后再做（Issue 明确「输出格式等后端表结构定了再对齐」）。

## 文件

| 文件 | 作用 |
| --- | --- |
| `personas.json` | 组织（上级部门 + 6 个叶子部门）与规格里有名有姓的人，字段照规格表 |
| `gen_personas.py` | 只用 Python 3.12 标准库；按固定种子把每个部门补足到规定人数，输出 `people.json` |
| `test_gen_personas.py` | unittest 验收用例 |
| `README.md` | 本文 |

## 运行

```powershell
# 在工作目录（仓库根）执行，或任意目录执行（脚本会自动定位同目录下的 personas.json）
python gen_personas.py --seed 20261016 --out <输出目录>
```

- `--seed`：固定随机种子（必填）。同一种子两次生成逐字节相同。
- `--out`：输出目录（必填，不存在会自动创建），结果写到 `<输出目录>/people.json`。

运行测试：

```powershell
python -m unittest ops/synthetic-data/test_gen_personas.py
```

## 为什么是 JSON 而不是 YAML

任务原要求 `personas.yaml`，但生成器「只用 Python 3.12 标准库」——标准库没有 YAML 解析器。按任务说明改用 JSON：`personas.json`。字段语义与 YAML 版完全一致，仅换载体格式。

## 数据模型

### personas.json · departments（组织）

| 字段 | 说明 |
| --- | --- |
| `name` | 部门名 |
| `parent` | 上级部门名；无上级为 `null`。`生产中心` 是上级部门，不是空间（`is_space=false`） |
| `is_space` | 是否部门空间（叶子部门）。规格：叶子部门 = 部门空间 |
| `headcount` | 在职人数（仅叶子部门有；`生产中心` 为 `null`） |
| `head` | 部门负责人姓名；空缺为 `null` |
| `head_acting` | 是否代负责人（仅 `质检部` 为 `true`，对应规格「赵一鸣……代部门负责人」） |
| `space_admin` | 空间管理员姓名；仅 `人事行政`（周宁）、`信息部`（顾远）按规格填写，其余为 `null` |
| `prefix` | 编号前缀（规格：A 装配一部、B 装配二部、Q 质检部、W 仓储物流、H 人事行政、I 信息部） |
| `base_position` | 生成人（无名人）的基线岗位，见下方「最少假设」 |

### personas.json · people（有名有姓的人）

| 字段 | 说明 |
| --- | --- |
| `id` | 编号（`前缀+4 位数字`）。规格表格中已有编号的原样保留；段落里点名但未给编号的（宋立、冯敏、韩冬、钱程、邵阳、方圆、冯涛）为 `null`，由生成器续编 |
| `name` | 姓名 |
| `department` | 部门（叶子部门） |
| `position` | 岗位 |
| `hire_date` | 入职日期（`YYYY-MM-DD`）。段落点名的人规格未给日期，为 `null`，由生成器补 |
| `resign_date` | 离职日期（`YYYY-MM-DD`）；在职为 `null` |
| `status` | `active`（在职）/ `resigned`（离职） |
| `account` | 平台账户状态：`active`（有账户）/ `none`（无账户，严述）/ `disabled`（已停用，离职档案） |
| `platform_roles` | 具体平台角色（不含基础「员工」角色，见下方角色规则） |
| `note` | 特殊情况（照规格表「特殊情况」列原文） |

### people.json（生成结果）

顶层为 `{"seed": <种子>, "people": [...]}`，`people` 共 196 条，按 `id` 排序。每个人的字段同 `personas.json` 的 people，但：

- 补齐了 `id`（无名的续编）与 `hire_date`（无名的按种子生成）；
- `platform_roles` 已套用「员工」角色规则（见下），为最终角色列表。

`people` 构成：在职 190（其中 189 有账户、严述 1 人无账户）+ 离职档案 6。

## 角色规则（照规格）

> 所有人都另有角色「员工」，严述和已离职档案除外。

- 在职且**有账户**（`status=active` 且 `account=active`）：`platform_roles = ["员工"] + 具体角色`。
- 严述（`account=none`）：无任何平台角色。
- 离职档案（`account=disabled`）：无任何平台角色。

## 最少假设（规格未写、本表所做的选择）

规格没写、拿不准的地方按「最少假设」处理，全部列在这里，不扩展规格：

1. **生成人的岗位**：无名人取本部门基线岗位 `base_position`——装配一部/二部→装配工、质检部→检验员、仓储物流→叉车工（均取自规格已有岗位）；人事行政→专员、信息部→工程师（规格未给这两个部门的普通岗位，此处为占位，待后端表结构定稿后对齐）。
2. **陈默的状态**：规格「10-10 离职，交接中」。因其仍在装配二部 54 人的在职人数里、且平台角色仍是「班组长」，按**在职**处理，离职状态记入 `note`。
3. **离职档案 6 份**：规格只点明 张燕（A0102，2025-11-30 离职）。其余 5 份由生成器按固定种子补：部门用种子随机分配到叶子部门、岗位取基线岗位、日期在合理区间（见第 5 条）。
4. **生成人姓名**：三字名（单姓 + 双字名），从常见姓、名用字按种子随机组合；保证不与规格里的人重名、彼此不重名（张燕、王磊为规格内既定重复）。
5. **生成日期区间**（合成数据，非真实）：
   - 无名人（在职）与段落点名者入职日期：`2019-01-01` ~ `2026-09-30`。
   - 离职档案：入职 `2018-01-01` ~ `2024-06-30`，离职 `2024-07-01` ~ `2026-09-30`（保证离职晚于入职）。
6. **编号续编**：每个部门前缀从规格中该部门已有编号的最大号 +1 起递增（例如 装配一部已有最大 A0219，续编从 A0220 起）。
7. **张燕 A0102 的「2025-11-30 离职」**：从「特殊情况」列归一化到 `resign_date` 字段，`note` 置空（离职信息不重复存放）。
